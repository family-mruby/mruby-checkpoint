# checkpoint 形式 v1

> 状態: P4 で実装済 (mruby 側の書き出しと復元、SabiRuby のリーダー)、P5b で任意のセクションに長さを足した、P6 でソースのセクション `SRC0` を足した、F1 で埋め込む側のセクション `EMB0` を足した、F4 で呼ぶメソッドの名前のセクション `SND0` を足した | 更新: 2026-11-04 | v0 (`doc/format_v0.md`) を置き換えた

mruby の VM で動いているプログラムの状態 (ヒープ・実行のコンテキストごとのフレームと VM
スタック・Task のスケジューラ) を、別の `mrb_state`・別のプロセス・別のポインタ幅・別の VM
実装で続きから動かすための形式。C の構造体の写しではなく、mruby の意味論の層で定める。
この文書だけを読んで復元側を書けることを目標にする。

v0 からの変更は §16 にまとめた。v0 のイメージは読まない (外に読み込み側がいないため)。

## 1. 考え方

- **論理グラフ**。オブジェクトに 1 から通し番号を振り、参照は番号で書く。ポインタは書かない。
- **普段の実行では何もしない**。書き出す瞬間に、実行中の内部表現 (ポインタ・シンボル ID・
  irep) を名前・番号・内容のハッシュに置き換える。
- **permanent** (= 書き出し側で VM を開いた直後に既にあったもの。組み込みのクラス・
  モジュール・mrblib のメソッドなど) は中身を運ばず**名前**で運び、読む側の同じ名前のものに
  結びつける。運ぶのはプログラムが作ったものと、permanent なものへの変更分。
- **実行のコンテキスト**。mruby の実行のコンテキスト (`struct mrb_context`: VM スタックとフレームの並び)
  は、プログラムの本体 (root) のほかに、Fiber ごと・Task ごとに 1 つある。v1 はそれを全部運ぶ。
  どのコンテキストが実行中だったか、Task がスケジューラのどのキューのどの順にいたかも運ぶ。
- 値の内部表現は固定: Integer は 64 bit 符号つき、Float は IEEE 754 倍精度、String はバイト列
  (UTF-8 として扱う)。ポインタ幅に依らない。

## 2. 基本の符号化

- 整数はすべて**ビッグエンディアン**。`u8` `u16` `u32` `u64`。符号つきは 2 の補数で、`i32` は
  `u32` と同じ 4 バイト。
- `str` = `u32` の長さ + その長さのバイト列 (終端の 0 は無い)。
- `ref` = `u32`。0 は「無し」(C の NULL、Ruby の nil ではない)。1 以上は表の番号。
  シンボル・irep・オブジェクト・コンテキスト・Task はそれぞれ別の表で、番号も別。
- `sym` = シンボル表への `ref`。

## 3. 全体の並び

| 順 | 中身 |
|---|---|
| 1 | ヘッダ |
| 2 | シンボル表: `u32` 個数 + 各 `str` (名前)。番号は出てきた順に 1, 2, ... |
| 3 | irep 表: `u32` 個数 + 各 irep レコード (§6) |
| 4 | オブジェクト表: `u32` 個数 + 各オブジェクトレコード (§7) |
| 5 | 変更表: `u32` 個数 + 各変更レコード (§9) |
| 6 | コンテキストの表: `u32` 個数 K (1 以上) + K 個のコンテキストレコード (§10) |
| 7 | 今のコンテキスト: `u32` (コンテキストの番号、1〜K。書き出したとき実行中だったコンテキスト) |
| 8 | スケジューラ (§11) |
| 9 | 任意のセクション (§13。タグ 4 バイト + `u32` 長さ + 中身、0 個以上) |
| 10 | 終端タグ `END0` |

ファイルの終わりは `END0` の終わりと一致する。余りがあれば壊れている、`END0` が無ければ
途中で切れているとみなして断る。

### ヘッダ

| 型 | 中身 |
|---|---|
| 4 バイト | `MRCK` |
| `u16` | 形式の版 = 1 |
| `str` | 書いた処理系の版 (例 `mruby 4.0.0`) |
| `str` | バイトコードの版 = `RITE0400` |
| `u8` | Integer のビット数 = 64 |
| `u8` | Float のビット数 = 64 |
| `u8` | String が UTF-8 なら 1 |
| `u8` | 書いた側のポインタ幅 (情報のみ。読む側は使わない) |

読む側は版と値の内部表現 (64 / 64 / 1) が合わなければ断る。64bit 版と 32bit 版の mruby が書く
イメージは、最後の 1 バイト以外同一になる。

## 4. 値

`値` = タグ `u8` + 中身。

| タグ | 意味 | 中身 |
|---|---|---|
| 0 | nil | なし |
| 1 | false | なし |
| 2 | true | なし |
| 3 | Integer | `u64` (int64) |
| 4 | Float | `u64` (IEEE 754 倍精度のビット列) |
| 5 | Symbol | `sym` |
| 6 | オブジェクト | オブジェクト表への `ref` (0 は来ない) |
| 7 | undef (VM 内部の「値なし」。レジスタの中にだけ現れうる) | なし |

64 bit に収まらない Integer はオブジェクト (§7 の種類 16) として運ぶ。

## 5. シンボル

名前で運ぶ。読む側は名前から自分のシンボルを引く (無ければ作る)。シンボル ID の数値は
処理系・プロセスごとに違ってよい。

## 6. irep (コードの塊)

irep はメソッド・ブロック・トップレベルのコード 1 つ分。**内容のハッシュ**で識別する
(§6.3)。レコードの先頭は種類 `u8`: 0 = 運ぶ、1 = permanent (ハッシュだけ)、2 = permanent で
中身も運ぶ。

### 6.1 運ぶ irep (種類 0)

| 型 | 中身 |
|---|---|
| `u8` | 0 |
| `u64` | 内容のハッシュ (読む側は組み立て後に計算し直して照合する) |
| `u16` | nlocals: ローカル変数の数 (self を含む) |
| `u16` | nregs: 使うレジスタの数 |
| `u16` | clen: 例外処理の表の行数 |
| `u32` | ilen: 命令列のバイト数 |
| バイト列 | 命令列 ilen バイト + 例外処理の表 13×clen バイト |
| `u16` | plen: 定数プールの個数 |
| 各プール | 種類 `u8` + 中身: 0 = 文字列 `str` / 1 = 整数 `u64` (int64) / 2 = 浮動小数 `u64` (ビット列) / 3 = 多倍長整数 `str` (mruby の内部の詰め方: 長さ、基数、数字) |
| `u16` | slen: シンボルの個数 |
| 各 `sym` | 命令が使うシンボル (0 は「無し」) |
| `u16` | rlen: 子の irep の個数 |
| 各 `ref` | 子の irep (irep 表の番号。0 は無し。子の数があって表の無い irep は全部 0) |
| `u16` | ローカル変数名の個数 (nlocals − 1 か 0) |
| 各 `sym` | ローカル変数名 (R1 から順。0 は無名) |

- 命令列は mruby 4.0 のバイトコード (RITE 04.00 の命令表。`OP_EXT1..3` を含む) で、`.mrb`
  ファイルの IREP の命令列と同じ。オペランドのシンボル・プール・子 irep の番号は、この irep の
  中の表の添字 (0 起点)。
- 例外処理の表の 1 行は 13 バイト: 種類 `u8` (0 = rescue, 1 = ensure)、開始 `u32`、
  終了 `u32` (含まない)、飛び先 `u32`。いずれも命令列の中のバイト位置。
- 行番号は任意のセクション `DBG0` (§13) で運ぶ。

### 6.2 permanent な irep (種類 1、2)

| 型 | 中身 |
|---|---|
| `u8` | 1 か 2 |
| `u64` | 内容のハッシュ |
| (種類 2 のみ) | §6.1 の nlocals からローカル変数名までと同じ |

- 書く側は、表に入る permanent な irep (mrblib のもの) をすべて種類 2 で書く。permanent な
  irep が表に入るのは、生きたコードが要るときだけ: フレームが動かしている (§7 の種類 15)、実行中に
  作られた Proc が持っている (mrblib の中のブロック)、そのどちらかの子孫。他の mrblib の
  メソッドは名前 (§8) で結ぶ。
- 読む側は、同じハッシュの permanent な irep を自分が持っていればそれを使い (同じビルドどうし。
  中身は読み飛ばす)、無ければ中身から組み立てる (別の版の mrblib を持つ処理系)。組み立てたものは
  ハッシュを計算し直して照合する。種類 1 は書かれないが、読む側は受け付けてよい (自分の irep が
  無ければ断る)。

### 6.3 内容のハッシュ

FNV-1a 64 bit (初期値 `0xcbf29ce484222325`、乗数 `0x100000001b3`、1 バイトずつ xor してから
掛ける)。下の順にバイト列を流す。`U(x)` は x を `u64` のビッグエンディアン 8 バイトにしたもの。

1. `U(nlocals)` `U(nregs)` `U(clen)` `U(ilen)`
2. 命令列 + 例外処理の表 (ilen + 13×clen バイト)
3. `U(plen)`、各プール: 整数 `U('i')` `U(値)` / 浮動小数 `U('f')` `U(ビット列)` /
   多倍長 `U('b')` `U(長さ)` バイト列 / 文字列 `U('s')` `U(長さ)` バイト列
   (`'i'` などは文字コードの数値)
4. `U(slen)`、各シンボル: 無しなら `U(0xffffffffffffffff)`、あれば `U(名前の長さ)` + 名前
5. `U(rlen)`、各子: 子のハッシュ (無しなら 0) を `U()` で

ローカル変数名とデバッグ情報はハッシュに入れない。

## 7. オブジェクト

表の i 番目のレコードがオブジェクト i。参照は前にも後ろにも向いてよい (循環あり)。読む側は
2 回なめる: 1 回目で全部の器を作り (permanent は名前で引く)、2 回目で中身を埋める。

レコードの先頭は種類 `u8`。種類 1 と 15 以外は続けて共通ヘッダを持つ:

| 型 | 中身 |
|---|---|
| `ref` | クラス (そのオブジェクトの `class` が指すもの。特異クラスがあればそれ。0 はクラスを持たない内部のオブジェクト) |
| `u8` | frozen なら 1 |

### 種類ごとの中身

| 種類 | 名前 | 共通ヘッダの後 |
|---|---|---|
| 1 | permanent | (共通ヘッダなし) `str` 名前 (§8) |
| 2 | Object | ivar の並び |
| 3 | String | `str` 中身 |
| 4 | Array | `u32` 個数 + 各 `値` |
| 5 | Hash | `u8` 既定値のフラグ (bit0 = 既定値あり、bit1 = 既定値は Proc) + `u32` 組数 + 各 (`値` キー, `値` 値) + ivar の並び |
| 6 | Range | `値` 始め, `値` 終わり, `u8` (bit0 = 終わりを含まない、bit1 = まだ初期化されていない: `Range.allocate`) |
| 7 | Exception | `値` メッセージ (nil か String), `値` バックトレース (nil か String の Array) + ivar の並び |
| 8 | Class | クラスの中身 (下) |
| 9 | Module | クラスの中身 |
| 10 | 特異クラス | クラスの中身 |
| 11 | 取り込みクラス | `ref` スーパークラス (共通ヘッダのクラスは、取り込んだモジュール) |
| 12 | Proc | Proc の中身 (下) |
| 13 | Env | Env の中身 (下) |
| 14 | C のデータ | `str` 型の名前 + `str` 中身 (型ごとの関数が書いたバイト列) + ivar の並び |
| 15 | フレームが動かす permanent な Proc | (共通ヘッダなし) `str` 名前 (§8、`M:` の名前) + `ref` irep (§6.2 の種類 2) |
| 16 | 64 bit に収まらない Integer | `u8` 負なら 1 + `str` 絶対値の 16 進の数字 (ASCII、小文字) |
| 17 | Struct | `u32` 個数 + 各 `値` (メンバの値。メンバの名前はクラスの側にある) + ivar の並び |
| 18 | Set | `u32` 個数 (`0xffffffff` は Set.allocate のまま初期化されていない) + 各 `値` (要素) + ivar の並び |
| 19 | Rational | `str` 分子 (10 進) + `str` 分母 (10 進) |
| 20 | Complex | `u64` 実部 + `u64` 虚部 (IEEE 754 倍精度のビット列) |
| 21 | break (ensure 節を通る break・return・jump の途中の内部オブジェクト。レジスタにだけ現れる) | `u8` 種類 (0 = break、1 = jump、2 = stop) + `u32` 行き先のフレームの番号 (そのコンテキストのフレームの添字) + `値` |
| 23 | Random (mruby-random) | `u64` PCG の状態 + `u32` 最後のシード + ivar の並び |
| 24 | 前置きされたクラスの origin | (共通ヘッダのクラスは、そのクラス自身) `ref` スーパークラス + `u8` メソッド表があれば 1 + `u32` メソッドの数 + 各メソッド |
| 25 | String (binary のフラグつき: `String#b`) | 種類 3 と同じ |
| 26 | Task | `u32` Task の番号 (§11 の Task の表) + ivar の並び |
| 27 | Fiber | `u32` コンテキストの番号 (§10。0 は `Fiber.allocate` のまま初期化されていない) |

- 22 は使っていない。
- **種類 15** は、いずれかのフレーム (§10) の Proc が mrblib のメソッドの Proc のときに、種類 1 の
  代わりに使う。同じビルドの読み込み側は名前で引いた Proc をそのまま使い、mrblib の違う読み込み側は、
  運ばれた irep を本体とする Proc を新しく作ってフレームに使う (メソッドの持ち主のクラスは名前から、
  strict と scope は立てる)。その Proc を `upper` に持つブロックも同じものを指す。
- **種類 26 (Task)** のオブジェクトと Task の表の項目は 1 対 1。Task の中身 (状態、キュー、コンテキスト) は
  §11 にある。`Task.current` を root で呼ぶと作られる「main の Task」も Task の表にある。
- **種類 27 (Fiber)** のコンテキストは、その Fiber のもの (`Fiber.new`)、または `Fiber.current` が
  作ったもの (root のコンテキストや Task のコンテキストを指すことがある)。

**ivar の並び** = `u32` 個数 + 各 (`sym` 名前, `値`)。並びの順に入れる (順序を保つ)。
クラスの「ivar」には定数・クラス変数 (`@@x`) と、処理系の内部用の変数 (`__classname__`
= 名前のシンボル (トップレベル) かパスの String、`__outer__` = 外側のクラス、`__attached__` =
特異クラスの持ち主) も入る。Hash の既定値・既定の Proc は ivar `ifnone` として入る。

**Hash と Set の中身**は、読む側で全部のオブジェクトとメソッドとコンテキストがそろってから入れ直す
(キーのハッシュ値は読む側で計算し直す。`hash` / `eql?` が利用者のメソッドでもよい。並び順が
挿入順になる)。入れる順は、番号の大きいものから (Hash や Set をキー・要素に持つものは、その中身が
そろってから計算し直す。書く側は外から順に番号を振るので、中のものほど番号が大きい)。利用者の
`hash` / `eql?` が例外を上げたり、入れ直している Hash の大きさを変えたりしたら、復元を断る
(CRuby の Marshal.load と同じく、復元で利用者のコードが走る)。

**クラスの中身** (8, 9, 10):

| 型 | 中身 |
|---|---|
| `ref` | スーパークラス (superclass。取り込みクラスを挟むことがある。0 は BasicObject の上) |
| `u8` | インスタンスの種類: 0 = 未指定 (スーパークラスに従う)、1 = Object、2 = Exception、3 = String、4 = Array、5 = Hash、6 = Range、7 = Proc、8 = C のデータ、9 = Struct、10 = Set、11 = Complex、12 = Rational、13 = 多倍長整数、14 = Random |
| `u8` | bit0 = allocate 禁止、bit1 = 継承済みのフラグ (無視してよい)、bit2 = prepend されている (メソッドは種類 24 の origin にある)、bit3 = メソッド表を持つ (空でも) |
| ivar の並び | |
| `u32` | メソッドの数 |
| 各メソッド | `sym` 名前、`u8` 可視性 (0 public, 1 private, 2 protected)、`u8` 種類 + 中身: 0 = Proc (`ref`)、1 = C の関数 (`str` 名前 (§8 の `F:`) + `u32` 引数の仕様 (mruby の aspec))、2 = undef (このクラスで未定義にした) |

**Proc の中身**:

| 型 | 中身 |
|---|---|
| `u8` | bit0 = lambda、bit1 = orphan (return の行き先がもう無い)、bit2 = scope (メソッドの本体。return はここで止まる) |
| `u8` | 本体の種類: 0 = irep、1 = C の関数、2 = 別名 (`alias_method` で Ruby のメソッドに付けた名前) |
| | 0 なら `ref` irep / 1 なら `str` 関数の名前 + `u32` 引数の仕様 (最上位ビットが立っていれば下位 31 bit が aspec (0 は「引数を数えない」)、最上位ビットが 0 なら「引数なし」) / 2 なら `sym` 元のメソッド名 |
| `ref` | 外側の Proc (ブロックが書かれたメソッド・ブロック。別名では元のメソッドの Proc。無ければ 0) |
| `u8` | 環境の種類: 0 = 無し、1 = Env、2 = 定義先のクラス |
| `ref` | その Env かクラス |

**Env の中身** (ブロック・クロージャが捕まえたローカル変数の箱):

| 型 | 中身 |
|---|---|
| (共通ヘッダのクラス) | 定義先のクラス (target class) |
| `sym` | そのフレームのメソッド名 |
| `u8` | 長さ (変数の数。R0 = self を含む) |
| `u8` | ブロック引数のレジスタ番号 |
| `u8` | 可視性のフラグ (bit0-1 = 既定の可視性、bit2 = 可視性の区切り、bit3 = module_function 中) |
| `u8` | 1 = スタック上 / 0 = 切り離し済み |
| | スタック上なら `u32` コンテキストの番号 (§10) + `u32` そのコンテキストのスタックの位置 / 切り離し済みなら 長さ ぶんの `値` |

- **スタック上の Env** は、まだ実行中のフレームのレジスタそのものを指している (フレームのレジスタと
  クロージャから見える変数は同じ場所)。位置は §10 のそのコンテキストのスタック配列の添字で、必ずその
  コンテキストのどれかのフレームの R0 の位置に一致し、そのフレームの「環境」がこの Env を指す。読む側は Env の中身を
  別に持たず、そのコンテキストのスタックを共有させること。
- 終了した Task のコンテキストのフレームの Env がスタック上のまま残っていることがある (mruby-task は Task が
  終わっても切り離さない)。終了したコンテキストのフレームを持たない読み込み側は、そのコンテキストのスタックの値で切り
  離してよい (§10 の終了したコンテキスト)。

### C のデータの型 (種類 14)

型の名前が空 (`""`) のものは、型も中身もまだ無い (`Regexp.allocate`、`File.allocate` などで
作っただけ) C のデータ。中身の `str` は空。

| 型の名前 | 中身 |
|---|---|
| `Time` | `u64` 秒 (int64) + `u64` ナノ秒 (int64) + `u8` 時間帯 (1 = UTC、2 = 地方時) |
| `Regexp` | 空。パターンとフラグは ivar `@source`・`@flags` にあり、読む側はそれから組み立て直す |
| `MatchData` | `u64` 捕獲の数 n + 2n 個の `u64` (各捕獲の始まりと終わりのバイト位置、int64、無しは −1)。元の文字列と Regexp は ivar `source`・`regexp` にある |
| `CombinationState` (`Array#combination` などの途中) | `u64` k + `u64` n + `u64` 方式 + `u8` 位置の表があれば 1 + k 個の `u64` 位置 |
| `ary_product_generator` (`Array#product` のブロック付きの途中) | `u64` 全体の数 + `u64` いまの位置 |
| `Task::Queue` (v1) | `u8` 閉じていれば 1。中身は ivar `@items` (Array) にある。待っている Task は §11 の Task の表が、このオブジェクトを指す |
| `Checkpoint::Box` | `u64` 値 (試験用) |

## 8. permanent の名前

書く側と読む側は、どちらも VM を開いた直後 (プログラムを読む前) の状態を同じ手順でなめて、
permanent なものに名前を付ける。名前が同じなら同じものとみなす。

| 形 | 指すもの |
|---|---|
| `T` | トップレベルの self (main) |
| `Object`, `Integer`, `Math::DomainError` | クラス・モジュール。そのクラス自身の名前。名前の無いものは届いた定数のパス (Object の直下は `Object::` を付けない) |
| `S:<名前>` | `<名前>` の特異クラス (`S:T` は main の特異クラス) |
| `I:<名前>/<k>` | `<名前>` の直上に並ぶ k 番目 (0 起点) の取り込みクラス |
| `M:<名前>#<メソッド>` | そのクラスのメソッドの Proc (mrblib で Ruby で書かれたものなど) |
| `E:<名前>#<メソッド>` | その Proc の Env |
| `F:<名前>#<メソッド>` | メソッド表にある C の関数 |
| `F:attr_reader`, `F:attr_writer` | attr_reader / attr_writer が作るクロージャの C の関数 |
| `F:Struct.new#a`, `F:S:Data.define#members` など | 実行中に作られるクラスに gem が入れる C の関数 (作るクラスの中の名前) |
| `F:<埋め込む側の名前>` | 埋め込む側が名前を付けた C の関数 (`mrb_checkpoint_register_func`) |
| `V:<名前>@<ivar か定数>` | クラスの ivar・定数が持つオブジェクト |
| `G:$<名前>` | グローバル変数が持つオブジェクト |
| `X:nomem_err`, `X:stack_err` | 処理系が前もって作っておく例外 |

なめ方: `F:attr_*` → `T` → `Object` から深さ優先 → `S:T` → グローバル変数 → 前もって作る例外 →
実行中に作られるクラスの C の関数 → 埋め込む側の C の関数。1 つのクラスでは、メソッド (名前順)
→ 直上の取り込みクラス → 特異クラス → ivar と定数 (名前順。クラス・モジュールを指す定数は
そこで深さ優先に下る)。スーパークラスにも名前を付ける (`BasicObject` のように、定数がそのクラス
自身の中にしか無いもの)。定数・ivar が指すただのオブジェクトに特異クラスがあれば `S:<名前>`。
最初に付いた名前を使い、同じものに二度は付けない。名前順はシンボル名のバイト順。

VM を開いた直後のオブジェクトは、プログラムが参照を手放しても回収されない (書く側も読む側も
持ち続ける)。名前とアドレスの対応が崩れないようにするため。

名前の一覧は `checkpoint names` で出る。別の処理系は表を持たず、名前を自分のクラスの表をたどって
引く。

## 9. 変更表

permanent なものへの変更を、読む側の permanent なものに当てる。各レコードは種類 `u8` で
始まる。対象 (`ref`) は permanent のオブジェクト。

| 種類 | 名前 | 中身 |
|---|---|---|
| 1 | メソッドの定義 | `ref` クラス + メソッド 1 つ (§7 のクラスの中身と同じ形) |
| 2 | メソッドの削除 | `ref` クラス + `sym` |
| 3 | ivar・定数の設定 | `ref` オブジェクト + `sym` + `値` |
| 4 | ivar・定数の削除 | `ref` オブジェクト + `sym` |
| 5 | スーパークラスの付け替え | `ref` クラス + `ref` 新しいスーパークラス (permanent なクラスへの include) |
| 6 | グローバル変数の設定 | `sym` + `値` |
| 7 | グローバル変数の削除 | `sym` |
| 8 | permanent な Random の状態 (既定の乱数) | `ref` オブジェクト + `u64` 状態 + `u32` 最後のシード |
| 9 | permanent なクラスのマーカー | `ref` クラス + `u8` bit0 = prepend されている |
| 10 | permanent な String / Array / Hash の中身 | `ref` オブジェクト + `u8` frozen + `u8` 型 (3 / 4 / 5) + 中身 (String: `str`、Array: `u32` + 各 `値`、Hash: `u32` + 各 (`値`, `値`)。Hash は他の Hash と同じく最後に入れ直す) |

プログラムが定義したトップレベルのクラスは「Object への定数の設定」として、トップレベルの
`def` は「Object へのメソッドの定義」(private) として現れる。

C の側の GC のルート (`mrb_gc_register` が持つ隠れたグローバル変数とその Array。mruby-task は Task をここに
登録する) は、プログラムのものではないので書かない。読む側のスケジューラと埋め込む側が、自分の
ものを登録する。

## 10. 実行のコンテキスト

コンテキストの表の 1 番は root (プログラムの本体のコンテキスト)。2 番からは Task のコンテキスト (Task の表の順に)、
その後に Fiber のコンテキストが、届いた順に並ぶ。

**コンテキスト**:

| 型 | 中身 |
|---|---|
| `u8` | 状態: 0 = 未開始、1 = 実行中、2 = ほかを resume して待機中、3 = 中断中 (yield した)、4 = transfer して待機中、5 = 終了 (mruby の `mrb_fiber_state`) |
| `u8` | bit0 = C から resume された (`vmexec`。実行中の Task のコンテキストで立つ。§15) |
| `ref` | prev: このコンテキストを resume したコンテキスト (yield・終わりで戻る先。0 は無し) |
| `ref` | このコンテキストの Fiber オブジェクト (0 は無し) |
| `u32` | スタックの長さ L |
| L 個の `値` | スタック配列 (レジスタの並び) |
| `u32` | フレームの数 N |
| N 個のフレーム | 下 (一番外) から上 (いま実行中の、または待っているフレーム) の順 |

- フレームの無いコンテキスト (N = 0): 終了した Fiber、mruby-task がフレームを手放した Task のコンテキスト、そして root が
  フレームを持たないこと (スケジューラを C から回す埋め込む側。§12) がある。L も 0。
- 状態 0 の Fiber のコンテキストは、ブロックのフレーム (pc 0) と、その写し (pc 0) の 2 枚を持つ (mruby の
  `init_fiber`)。Task のコンテキストの状態は、Task が動いた後も 0 のことが多い (mruby-task は Task の
  コンテキストの状態を変えない。Fiber を resume すると 2 や 1 になる)。
- 終了したコンテキスト (状態 5) のフレームは意味を持たない。終了した Task のコンテキストは最後のフレーム (pc は命令列の
  終わり) を持ったままのことがある。

**フレーム** (呼び出し 1 つ分。mruby の callinfo):

| 型 | 中身 |
|---|---|
| `u8` | フレームの種類: 0 = Ruby のフレーム、1 = C の関数のフレーム (コンテキストの切り替えを待っている。下) |
| `sym` | メソッド名 (トップレベルやブロックでは 0 のことがある) |
| `ref` | 実行中の Proc (種類 0 では irep を持つもの。種類 1 では 0 か C の関数の Proc) |
| (種類 1 のみ) `str` | その C の関数の名前 (§8 の `F:`) |
| `u32` | レジスタの窓の始まり = このフレームの R0 のスタック上の位置 |
| `u32` | pc = Proc の irep の命令列の中のバイト位置 (`0xffffffff` は無し。種類 1 では常に無し) |
| `u8` | 位置引数の数 (15 = 1 つの Array に詰めて渡した) |
| `u8` | キーワード引数の数 (15 = 1 つの Hash に詰めて渡した) |
| `u8` | C から呼ばれたフラグ (常に 0。0 でないフレームは書かない) |
| `u8` | 可視性のフラグ (Env と同じ意味の 4 bit) |
| `ref` | 渡されたブロック (Proc。無ければ 0) |
| `u8` + `ref` | 環境: 0 = 無し / 1 = Env / 2 = 定義先のクラス |

- **レジスタの窓**: フレーム k の Ri はそのコンテキストのスタック配列の [始まり + i]。呼ばれた側の R0 (self) は
  呼んだ側の R[a] と同じ場所。呼ばれた側が戻ると戻り値はそこに入る。
- **pc**: 今のコンテキストのいちばん上のフレームでは「次に実行する命令」の位置。それより下のフレームでは「呼び出し
  から戻ったら実行する命令」(呼び出し命令の次) の位置。待っているコンテキストのいちばん上の Ruby のフレームも
  同じく次に実行する命令 (Task が切り替えで止まった所、`Fiber.yield` の前に止まった所)。
- スタックの長さは、いちばん上のフレームの始まり + そのフレームのレジスタの数 (と引数の分の大きい方)。
  それより上は nil とみなす。
- **死んだレジスタ**: 書く側は、各コンテキストの各フレームの命令列から「この先読まれない」と分かる一時
  レジスタ (ローカル変数より上) を nil として書く。値の意味は変わらない。読む側は何もしなくてよい。
- **C の関数のフレーム (種類 1)** は、今のコンテキストでないコンテキストのいちばん上にだけ現れる。その関数はコンテキストを
  切り替えるだけで、呼び出しの値は、切り替えて戻ってきた側が窓の始まりのレジスタに入れる。
  書く側が書くのは次の関数だけで、ほかの C の関数のフレームがあれば断る (§15):

  | 関数 | 意味 |
  |---|---|
  | `F:Fiber#resume` | このコンテキストは別の Fiber を resume して待っている (状態 2)。その Fiber が yield するか終わると、値がここに入る |
  | `F:Fiber#transfer` | このコンテキストは transfer して待っている (状態 4)。transfer で戻ると値が入る |
  | `F:S:Fiber#yield` | このコンテキスト (Fiber) は yield して中断中 (状態 3)。次に resume されると、resume に渡した値が入る |
  | `F:S:Task#run` | このコンテキストは Task のスケジューラのループを回している (`Task.run`)。その中で Task が実行されている |
  | `F:S:Task#pass` | このコンテキスト (root) は Task のスケジューラを 1 回だけ回している (`Task.pass`)。その中で Task が実行されている |

- 書き出しは命令の境目で行う。`Checkpoint.save` / `Checkpoint.suspend` では、今のコンテキストの
  いちばん上のフレームのその呼び出しの戻り先のレジスタに `resumed` のシンボルが入っている (書いた側の
  プログラムには `saved` が返る)。外からの要求 (§14) では、どのレジスタも書き換えない。

## 11. スケジューラ (mruby-task)

| 型 | 中身 |
|---|---|
| `u8` | bit0 = その境目でスケジューラが切り替えを要求していた (`task.switching`。実行中だった Task のタイムスライスがその境目で終わる。外からの要求が立てたフラグは含まない)、bit1 = スケジューラのループが回っていた (`Task.run` の中、または埋め込む側の `mrb_task_run` の中) |
| `u16` | 1 tick のミリ秒 (mruby-task の `MRB_TICK_UNIT`。既定 4) |
| `u32` | 書いたときの tick (時計) |
| `u8` + `i32` | 次に起きる時刻があれば 1 + その残りの tick (起きる tick − 書いたときの tick) / 無ければ 0 + 0 |
| `u32` | Task の数 T |
| T 個の Task | 下。キューごとに、キューの順に並ぶ: 休止 (dormant)、実行可能 (ready)、待機中 (waiting)、中断中 (suspended) の順。最後に main の Task (あれば) |
| `u32` | 実行中だった Task の番号 (Task の表の番号。0 は無し) |
| `u32` | 埋め込む側の Task の番号 (`mrb_checkpoint_set_host_task`。0 は無し) |

**Task**:

| 型 | 中身 |
|---|---|
| `ref` | Task のオブジェクト (§7 の種類 26) |
| `u32` | コンテキストの番号 (§10。main の Task は 0) |
| `u8` | 状態 (mruby-task の値): 0 = DORMANT、2 = READY、3 = RUNNING、4 = WAITING、8 = SUSPENDED |
| `u8` | キュー: 0 = dormant、1 = ready、2 = waiting、3 = suspended、255 = どのキューにもいない (main の Task) |
| `u8` | 優先度 (0〜255、小さいほど先) |
| `u8` | 待ちの理由: 0 = 無し、1 = sleep、4 = join、8 = Task::Queue |
| `u8` | タイムスライスの残り (tick。実行中だった Task はこの残りから続ける。§12) |
| `値` | 名前 (main の Task では nil。読む側は `"main"` にする) |
| `値` | 戻り値 (終了した Task の値、または捕まえなかった例外。main の Task では nil) |
| 理由ごとの中身 | sleep: `i32` 残りの tick / join: `u32` 待っている Task の番号 (0 は無し) / Task::Queue: `ref` Queue のオブジェクト (0 は無し) + `u8` 期限があれば 1 + `i32` 残りの tick |

- **キューの順**がそのまま運ばれる (同じ優先度の Task の順番、優先度を変えた後の待ちキューの並び)。
  読む側はキューを表の順に組み立てる (優先度で並べ直さない)。
- **残りの tick** は、書いたときの tick から数えた差 (負なら期限が過ぎている)。読む側は自分の
  今の tick に足して起きる時刻を決め直す。移動にかかった時間は待ちに含めない。
- **実行中だった Task** は、今のコンテキストが (prev をたどって) その Task のコンテキストから resume されたもの、
  または今のコンテキストがその Task のコンテキストであるもの。その境目で状態がもう RUNNING でないことがある
  (sleep した、自分を止めた、終えた: その場合はスケジューラが切り替えを要求している)。
- main の Task (`Task.current` を root で呼ぶと作られるもの) は、名前と戻り値を mruby-task が
  GC から守っていないので書かない (nil)。
- 終了した Task は、最後に待った理由と中身を残していることがある (mruby-task は消さない)。その
  待ち先がもう無ければ 0。
- **bit0 の見分け方** (書く側の作り): 外からの要求も同じ `task.switching` を立てて VM を止める。
  C mruby の書く側は、mruby-task が自分の切り替えの要求を数える数 (`switch_requests`、
  `patches/0002-task-switch-requests.patch`) を要求のときとセーフポイントで比べ、数が動いたか、要求の
  前からフラグが立っていれば bit0 を立てる。要求とセーフポイントの間に動いた命令が `Task.pass` でも、
  タイムスライスの終わりでも、起こされた Task でも同じに分かる。

## 12. 続きから動かす

読む側は全部を組み立ててから、書き出したときに実行中だったものを続ける。

1. **実行中だった Task が無い**: 今のコンテキスト (root、または root から resume された Fiber) のいちばん
   上のフレームの pc から動かす。今のコンテキストが Fiber なら、そこから戻る先は prev のチェーンのとおり。root の
   いちばん下のフレームが戻ればプログラムの終わり。§11 の bit0 が立っていれば、切り替えの要求を
   立てておく (root では意味を持たない)。
2. **Task が実行中だった**: その Task のタイムスライスの残りを、今のコンテキスト (その Task のコンテキストか、
   その Task が resume した Fiber) から続ける。§11 の bit0 が立っていれば、そのタイムスライスはその
   境目で終わっている (続けずに、終わった後の扱いだけをする: RUNNING なら READY に戻す、止まって
   いれば dormant に移して join を待つ Task を起こす)。タイムスライスが終わったら、スケジューラを
   入れた側 (実行中だった Task のコンテキストの prev。§10 の C の関数のフレーム) に戻る:
   - `Task.run`: ループの続き。その Task が READY なら同じ優先度の後ろに回す (round robin)。
     C mruby の読み込み側は、`Task.run` のフレームを落とし、呼んだ側の pc をその呼び出しの命令に戻して、
     呼び出しをやり直す (ループはキューの今の状態から回る)。
   - `Task.pass`: その 1 回は終わっている。呼び出しは nil を返し、root が続く。
   - root にフレームが無い (埋め込む側が C から `mrb_task_run` を回していた): ループの続きを回す。ループが
     終われば続きの処理は終わる (埋め込む側は、埋め込む側の Task の値を見る)。
3. タイムスライスは、記録された残りから続ける (書いた側と同じ tick でタイムスライスが終わる。同じイメージから
   何度続けても同じ動きになる)。残りが 0 でも 0 のまま (tick はそのタイムスライスを終わらせない。Task が
   自分から譲るまで続く。書いた側と同じ)。
4. 時計: 新しい VM に復元する読み込み側は、自分の tick を書いたときの tick にしてよい (残りの tick は
   そのまま)。プログラムが tick の値を持っていることがある (`Task::Queue#pop` の期限、`Task.tick`)
   ので、mruby の読み込み側はそうする。

## 13. 任意のセクションと終端タグ

スケジューラの後に、任意のセクションが 0 個以上続き、最後に `END0` が来る。任意のセクションは

| 型 | 中身 |
|---|---|
| 4 バイト | タグ |
| `u32` | 中身の長さ (バイト) |
| 長さぶんのバイト | 中身 (下の表) |

の形をとる。`END0` だけは長さを持たない (タグ 4 バイトで終わり)。

- 読む側は、知っているセクションの中身を読み、読んだ量が長さとちょうど一致しなければ壊れているとみなして
  断る (長さが残りのバイトより大きい場合も)。
- 知らないタグのセクションは、長さぶん読み飛ばす (断らない)。後からセクションを足しても、古いリーダーが読める。
- 書く側は、新しいセクションを足すときに既存のセクションの中身を変えない。中身の形を変えるときは新しいタグにする
  (`DBG1` など)。

| タグ | 中身 (長さの後) | 読む側 |
|---|---|---|
| `DBG0` | 行番号: `u32` 個数 + 各 (`ref` irep (運ぶ irep の番号) + `u16` ファイルの数 + 各ファイル (`str` ファイル名 + `u32` 始まりの pc + `u32` 終わりの pc + `u32` 個数 + 各 (`u32` pc, `u32` 行) 行が変わる位置)) | 運んだ irep に行番号を付ける (バックトレース・`__LINE__`・`source_location` に出る)。書く側は、行番号を持つ irep を、プログラムのものも permanent なもの (mrblib、種類 2) も書く。読む側は、自分の permanent な irep を使うときはそれ自身の行番号を使い (同じビルドなら同じ)、中身から組み立てた irep にはこのセクションの行番号を付ける。無視してもよい (行番号が出ないだけ) |
| `SRC0` | プログラムのソース (表示用): `u32` 個数 + 各 (`str` ファイル名 + `str` ソースのバイト列) | 表示だけに使う (インスペクタが各フレームの行の前後を出す)。実行には使わない。書く側は、頼まれたとき (`Checkpoint.save(path, source: true)` など。既定は書かない) だけ、`DBG0` が名前を出すファイルのうち、埋め込む側がソースを登録したものを書く。ファイル名は `DBG0` のファイル名と同じ文字列で、同じファイルは 1 度だけ。読む側は無視してよい。C の mruby の復元側はソースを登録し直す (後で書くイメージが、頼まれれば同じソースを運ぶため) |
| `GCS0` | GC の設定: `u8` (bit0 GC を止めている、bit1 世代別、bit2 割り当てごとに進める、bit3 スケジューラが進める) + `u32` interval_ratio + `u32` step_ratio + `u64` step_limit + `u64` malloc_threshold + `u64` debt_limit (int64) | GC の設定に当てる。書く側は VM を開いた直後と違うときだけ書く。GC の作りの違う処理系は無視してよい |
| `SND0` | プログラムのコードが呼ぶメソッドの名前: `u32` 個数 + 各 `sym` (名前の順、重なり無し) | 書く側は、プログラムの irep (permanent でないもの。ヒープの Proc が持つものとその子) の `OP_SEND`・`OP_SEND0`・`OP_SENDB`・`OP_SSEND`・`OP_SSEND0`・`OP_SSENDB` のシンボルのうち、書く側の基準のどれかのクラス・モジュールがメソッドとして持つ名前を、プログラムが自分で定義した名前 (自分のクラスのメソッド、permanent なクラスに足したメソッド) を除いて書く (1 つも無ければ書かない)。読む側は、自分の基準のどのクラス・モジュールも持たない名前を「足りない名前」として埋め込む側に渡す (`mrb_checkpoint_missing_names`)。**断らない** (プログラムが `respond_to?` や `rescue NoMethodError` で備えていることがある)。名前だけで見るので受け手のクラスは見ない。`super`・VM が自分で扱う演算子 (`[]`・`+` など)・名前を計算する `send`・まだ compile していない eval のコード・C からの呼び出しは入らない。同じ一覧は `mrb_checkpoint_sent_names` でイメージを書かずに取れる (止める前に相手に聞くため)。ほかの読む側は無視してよい |
| `EMB0` | 埋め込む側のバイト列 (`mrb_checkpoint_set_embedder` の dump が書いたもの、そのまま) | 埋め込む側のもの。C の mruby は、復元が誤りなく済んだあと、中身を埋め込む側の restore に渡す (`mrb_checkpoint_continue` の前)。gem は中身を読まない。ほかの読む側は無視してよい。書く側は、ほかのセクションの後、`END0` の直前に 1 つだけ書く (埋め込む側が登録したときだけ) |
| `END0` | なし (長さも無い) | ここで終わる |

## 14. 外からの要求

`mrb_checkpoint_request()` は、プログラムが `Checkpoint.save` を呼ばずに、外から書き出しを要求する
API。イメージの形は同じで、書き出す点が「要求の後の最初のセーフポイント」になる。どのレジスタも書き換えない
(`:resumed` は入らない)。要求とセーフポイントの間に動いた命令がスケジューラに切り替えを要求していれば、
§11 の bit0 が立つ。

## 15. 書き出しを断る場合

次のどれかに当たると、書き出し側は理由 (どのオブジェクトの、どの型か、どこから届いたか) を
添えて断る。`Checkpoint.save` などは `Checkpoint::Error` を上げ、プログラムは続く。外からの
要求は断りの報告の関数に渡される。

- **C の関数のフレーム**: C の関数が呼んだブロックの中 (`sort { }` など)、C の関数が resume した
  Fiber の中 (`mrb_fiber_resume`、そこから yield した Fiber が待っている C の関数を含む)、
  §10 の表に無い C の関数で待っているコンテキスト、スケジューラを `Task.run`・`Task.pass`・埋め込む側
  以外の C の関数が回している、同期の Task (`mrb_execute_proc_synchronously`) の中。C の
  スタックにあるフレームは運べない。
- **プロセスの資源**: 開いているファイル・ソケット・ディレクトリ (C のデータで、別表に登録の
  無いもの)。
- VM を開いた直後からあったのに名前の付かないオブジェクト (ObjectSpace からしか届かないもの)。
- 名前の無い C の関数から作った Proc (`mrb_checkpoint_register_func` で名前を付ければ運べる)。
- フレームが命令列の外に立っている (VM が命令列の終わりを越えて走っている。壊れた状態)。

キー・要素の `hash` / `eql?` が入れ直しで例外を上げる・Hash を変える Hash や Set は、復元で断る。
