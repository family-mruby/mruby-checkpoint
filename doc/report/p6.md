# P6 報告: プログラムのソースをイメージに入れる (表示用)

> 状態: 実装済・検収待ち | 更新: 2026-11-03 | ユーザの決定 (2026-11-03): 書き出すときに、ソースも任意のセクションとしてイメージに入れる

## 結果

- 書き出すときに頼めば、プログラムのソースを任意のセクション `SRC0` としてイメージに入れる。表示だけに使い、
  実行には使わない。既定は入れない。形式は v1 のまま (任意のセクションを 1 つ足しただけ。`doc/format_v1.md` §13)。
- インスペクタ (`tools/checkpoint_inspect.rb`) は、ソースがあれば、コールスタックの各フレームの行の前後 2 行ずつを
  出し、止まった行に印を付ける。CLI の `--stack` は `>`、HTML は色の帯と左の線と `▶` と太字。
- C の mruby の復元側は `SRC0` を読み飛ばさずに読み、ソースを登録し直す (後で書くイメージが、頼まれれば同じ
  ソースを運ぶ)。SabiRuby は知らないセクションとして読み飛ばす (SabiRuby の変更なしで、ソース入りのイメージを
  ソースなしと同じに続ける。試験で確かめた)。
- `vm.c` の patch は変えていない (命令数の比べは要らない)。

## API

| 層 | 入口 | 中身 |
|---|---|---|
| C (埋め込む側) | `mrb_checkpoint_add_source(mrb, filename, src, len)` | コンパイルするファイルのソースを、コンパイラに渡すファイル名 (`mrb_ccontext_filename`) で登録する。写しを持つ。同じ名前は置き換え |
| C (埋め込む側) | `mrb_checkpoint_set_include_source(mrb, on)` | `source:` を書かない `save` / `suspend` と、外からの要求 (`mrb_checkpoint_request`) で、ソースを入れるかの既定。既定は FALSE |
| Ruby | `Checkpoint.save(path, source: true)`、`Checkpoint.suspend(path, source: true)` | この呼び出しのイメージにソースを入れる。`source: false` は既定が「入れる」でも入れない |
| ドライバ | `checkpoint run --with-source prog.rb`、`checkpoint resume --with-source x.ckpt` | 既定を「入れる」にする。ドライバは `run` のとき prog.rb のソースをいつも登録する (登録だけでは何も書かない) |

## 形式 (`SRC0`)

`u32` 個数 + 各 (`str` ファイル名 + `str` ソースのバイト列)。書くのは、運ぶ irep の行番号 (`DBG0`) が名前を出す
ファイルのうち、登録してあるものだけ。同じファイルは 1 度だけ、`DBG0` に出てくる順。mrblib のファイルは登録が
無いので入らない。

## 読む側 (tools/lib)

- JSON (inspect JSON 版 1 のまま、足しただけ): 全体に `sources` (`{ファイル名: テキスト}`、無ければ `{}`)。
  `sections[]` の `SRC0` は `files: [{file, bytes}]` だけを持つ (テキストは `sources` の 1 か所)。`DBG0` が名前を
  出さないファイルのソースは `warnings` に、同じファイルが 2 度あれば壊れたイメージとして断る。
- 表示の規則 (`CheckpointImage.source_excerpt` と HTML の `sourceLines`、同じ規則): `sources[frame.file]` があり、
  Ruby のフレームで、まだ始まっていないフレーム (pc 0) でなければ、`line` の前後 2 行を出し、`line` に印。
  未開始のフレーム・C の関数のフレーム・mrblib のフレームは今までどおり `file:line` だけ。
- 差 (`diff`) は `sources` もセクションも比べない。ソースを入れたイメージと入れないイメージの差は空。
- 全部の記録の表示 (`checkpoint_inspect.rb x.ckpt`) は `sources: counter.rb (238 bytes)` の 1 行、HTML の
  「イメージの中身」も `SRC0` の行を出す。

## 大きさ

サンプル (64 bit、最初のイメージ) と、このリポジトリの外の少し大きいプログラム (Task 3 つが画面を描く例)。`SRC0` の分は、ソースの大きさ + ファイル名 + 20 バイト
(タグ・長さ・個数・2 つの長さ)。

| プログラム | ソース (バイト) | ソースなし | ソースあり | 増え方 |
|---|---|---|---|---|
| counter.rb | 238 | 500 | 768 | +54% |
| data_box.rb | 302 | 593 | 926 | +56% |
| method_middle.rb | 549 | 1530 | 2115 | +38% |
| block.rb | 677 | 1740 | 2445 | +41% |
| save.rb | 804 | 1972 | 2803 | +42% |
| task_fiber.rb | 895 | 3633 | 4561 | +26% |
| fiber_nested.rb | 1270 | 1939 | 3244 | +67% |

## 試験

`rake test` (SabiRuby つき) はすべて通る: サンプル 711、狙った点、インスペクタ 3292、試験一式のファズ (64・32、
本体と Task の 2 つの形)。`rake test:asan`・`rake test:stress` も 461 ずつ通る (ASan の指摘なし)。

足した試験:

- `test/samples/source.rb`: `Checkpoint.suspend(path, source: true)` で書いたイメージを、64 ⇔ 32 bit・同じ
  プロセス・SabiRuby で続け、ソースなしと同じ出力になる (ASan・stress の構成でも通る)。
- `tools/test_inspect.rb` の「sources (SRC0)」(約 220): `test/inspect/stack.rb` を `--with-source` ありとなしで
  (64・32 × 2 つの起動の形)。
  - なし: `sources` が空で `SRC0` も無く、`--stack` に行が出ない。
  - あり: `sources` がファイルそのもの、`SRC0` のファイル名と大きさ、JSON の形、`warnings` なし、
    イメージの大きさがちょうど `SRC0` の分だけ増える、他のフィールドはソースなしと全部同じ、差が空。
  - 各フレームの印の行 = そのフレームの `line` = バックトレースの行番号で、行の中身がファイルのその行。
    `--stack` の印も、mruby 自身が出したバックトレースの行に付く。
  - 未開始のフレームと mrblib のフレーム (`Array#each`) には出ない。
- C の読む側: ソース入りのイメージを 64・32 bit でソースなしと同じに続ける。続けた側の次のイメージは、
  頼まなければソースなし、`resume --with-source` なら復元で登録し直したソースを運ぶ。`source:` が
  ドライバの既定より優先する (既定なし: なし/あり/なし、既定あり: あり/あり/なし)。
- SabiRuby: ソース入りのイメージをソースなしと同じ出力で続ける (`SABIRUBY_DIR`/`SABIRUBY_BIN` があるとき)。
- HTML: ソース入りのイメージのページで、コールスタックの印の行が 1 つでその行が suspend の行、前後の行が 4 つ、
  「イメージの中身」に `SRC0` (ヘッドレスの Chromium)。

## サブの仮決め

- **既定は入れない**。入れるのは呼び出しごとの `source: true` か、埋め込む側の既定 (`--with-source`)。呼び出しの
  指定が既定より優先する。
- **登録と書き出しを分けた**。埋め込む側はコンパイルするたびに登録し (写しを持つ。大きさはソースぶん)、書くかは
  書き出すときに決める。登録したファイルでも、運ぶコードがそのファイルを指していなければ書かない
  (`DBG0` の名前で絞る)。
- **復元で登録し直す** (親の案は「再登録しなければ運ばない」)。続けた先にはソースのファイルが無いのが普通なので、
  イメージからしか取れない。登録し直しても、書くのは頼まれたときだけなので、既定の動きは変わらない。複数の
  端末を渡り歩くときに、途中からソースが消えないようにするため。
- ソースは表示用で、irep のハッシュにもコードの照合にも使わない。ソースと実際のコードが食い違っていても
  (登録の後でファイルを書き換えたなど) 検出しない。表示が違う行を指すだけ。
- 表示の前後は 2 行ずつ (CLI と HTML)。CLI の行は 6 字下げで始まる (既存の試験の「ローカル変数の行」と
  同じ扱いで、バックトレースとの照合を崩さない)。
- `sources` は全体のフィールドにした (フレームごとに抜き出しを持たせない)。GUI は `sources[frame.file]` と
  `line` で切り出す (`doc/inspect_json.md` §11)。

## 残件

- `eval`・`instance_eval` に渡した文字列のソースは入らない (`eval` が作る irep のファイル名は `(eval)` などで、
  登録が無い)。入れるなら `eval` のときに登録する口が要る。
- SabiRuby の `Checkpoint.save` / `suspend` は `source:` を受け付けない (引数の数の `ArgumentError`)。SabiRuby で
  続けたプログラムが、その後で `source:` つきの `save` / `suspend` を呼ぶと落ちる。`test/samples/source.rb` は
  そのため 1 度だけ呼ぶ。SabiRuby 側は
  `source:` を受けて無視するだけでよい (このリポジトリからは直さない)。
- ドライバ以外の埋め込む側 (Family mruby など) は、アプリを読むときに `mrb_checkpoint_add_source` を呼ぶ必要が
  ある。持ち込むときに、アプリのファイル名 (フルパスか相対か) を行番号の名前と揃える。
