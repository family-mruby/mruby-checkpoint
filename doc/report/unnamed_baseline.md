# 報告: 名前の無い基準のものへの変更を運ぶ (Fu)

> 状態: 実装済・検収待ち | 更新: 2026-11-06 | 2026-11-06 に Family mruby の `FmrbI18n` で見つかった不具合 (基準のときからある名前の無いものへの変更が黙って落ちる) を、ユーザの決定「gem で正しく運ぶ」どおりに直した

## 1. 結果

- 名前のあるもの (定数・クラスの ivar・グローバル変数・main など) から届く、VM を開いた時点からある名前の無い
  ものに、経路の名前を付ける (`V:FmrbI18n@STRINGS/{"en"}`、`V:CkBase@DEEP/{:list}/0/@@inner` など。
  `doc/format_v1.md` §8.2)。名前を付けたものは snapshot を持ち、変更は変更表 (§9) で運ぶ。
- Array・Struct・Set の要素、Hash のキー・値としてだけ持たれる String には名前を付けない (VM ごとの費用を払わ
  ないため)。持ち主のダイジェストがその String のバイト列も含み、運ぶときは新しい String として運んで、それを持つ
  名前のある入れ物を全部書き直す。
- 名前のあるものでも落ちていた変更も運ぶようにした: Struct のメンバ、Set の要素、Env (クロージャの変数。
  メソッドの `E:` も)、Exception のメッセージの差し替え、特異クラスを持つようになったこと (`def obj.m`、`extend`)、
  中身の変わったキーを持つ Hash の入れ直し。
- 運べない形は理由をつけて断る: 中の変わった C のデータ、名前の付かない Set の要素の変更。
- 名前の決まりの版を 2 に上げた (`MRB_CHECKPOINT_TABLE_VERSION`、`TBL0`)。形式の版は 1 のまま (4 章)。
- `rake test` は全部通る (run_tests 507 件 × 3 構成、表の試験 87 件、targeted、inspect 3,484 件、短い fuzz の差 0)。
  前は 461・87・3,259 件。増えたのは新しい試料 3 つの分。

## 2. 原因

### 2.1 どの段で落ちるか

基準 (`checkpoint_perm.c`) は、VM を開いた直後の状態をなめて名前を付け、名前を付けたものだけ snapshot (クラスなら
メソッドと ivar、String・Array・Hash なら中身のダイジェスト、Object なら ivar) を取る。書き出し
(`checkpoint_dump.c` の `w_patches`) は snapshot の一覧を回り、今と違うものだけを変更表に書く。

- 名前が付くのは、クラス・モジュールの ivar と定数の値 (`V:`)、グローバル変数の値 (`G:`)、main (`T`)、メソッドの
  Proc と Env (`M:`・`E:`)、前もって作る例外 (`X:`) だけで、**その中身には降りていなかった** (`name_value` は
  名前を付けて snapshot を取るだけ)。
- 中身のダイジェストは、要素がオブジェクトならその**アドレス**だけを混ぜる (`val_bits`)。`STRINGS["en"]` に語を
  足しても `STRINGS` の要素のアドレスは同じなので、`STRINGS` のダイジェストは変わらない。
- 中の `"en"` の Hash には snapshot が無いので、どこにも比べる所が無い。変更表に何も出ず、イメージに入らない。
  読む側は自分の基準 (`FmrbI18n.add` の前) のままの Hash を持ち、エラーも出ない。これが「黙って落ちる」。
- 名前の無いものをイメージが参照すると (ローカル変数が持つ、名前のあるものの中身を書き直した)、`w_object` が
  `object made by mrb_open has no name` で断る。中の Hash を差し替えた案で外の Hash の鍵 `"en"` (Hash が凍結して
  写した String。名前が無い) を書けなかったのはこれ。

### 2.2 同じ形の場合 (洗い出し)

| 19 | 名前の無いものを別の定数へ移す・入れ替える・取り出してローカルだけが持つ | 断る | 運ぶ |

| 21 | 基準のときからある C のデータの中を変える (登録した dump の書くバイト列が変わる) | 黙って落ちる | **断る** (理由つき) |

残り (黙って落ちうる、または断るもの):

- C の側からしか届かないもの (C の静的変数、`mrb_gc_register`、C のデータの構造体の中のポインタ) と、ObjectSpace
  からしか届かないもの。参照されれば今までどおり断る。中の変更は見えない。
- Set の要素の中の、さらに中 (Set の中の Array の中の Array)。Set のダイジェストは要素の 1 段目だけを含む。
- 経路が 400 バイトを超える所にある無名のクラス (`visit_class` が名前を 512 バイトの領域で作るため)。
- 登録の無い C のデータの中 (今までどおり見ない。埋め込む側の資源)。
- 名前を付けない String を C の側も指しているとき、着いた側の C の側は古い String を指す (2.3 の案 (c) の代償)。

## 3. 直し方と選んだ理由

### 3.1 案の比べ

| 案 | 中身 | 同一性 | VM ごとの費用 (32 bit、表あり) | 採否 |
|---|---|---|---|---|
| (a) 基準のダイジェストを中まで取り、変わったら「名前 + 経路」を書く。読む側が経路をたどる | ダイジェストは名前のあるものごとに 1 つ (今の slot)。経路は書くときに今の形から作る | 書く側は基準のときにどれがどこにあったかを知らない。構造を動かした (入れ替えた、2 か所に入れた) プログラムでは、今の経路が読む側の別のものに結び付き、別々のものが 1 つにまとまる・1 つのものが 2 つに分かれる (変わっていない側が書かれないため見つからない) | 0 B | 採らない |
| (b) 基準で経路の名前を付けて表に入れる | 名前ごとに snapshot | 基準のときのアドレスと名前の対応を持つので正確 | 1 つあたり `ptrs` 4 B + `obj_idx` 4 B + 中身のダイジェストの slot 9 B (Object は ivar の値の slot) = 約 17 B | **採る** |
| (c) 変わったものを中身ごと新しいものとして運び、名前のある親を張り替える | 名前を作らない | 外から参照される名前の無いものは、親を全部張り替えないと 2 つに分かれる。書く側は親を知らない | 0 B | String に限って (b) に混ぜる |

(b) を基本にし、数が多く外へ参照を持たない String だけ (c) にした。

- (c) を String に限ると、親を見つけるのは簡単になる: 名前を付けない String は「名前のある Array・Struct・Set・
  Hash の要素・キー・値として 1 か所だけ」にあるもの。書くときに、今それを持つ名前のある入れ物を名前の一覧から
  探して全部書き直す (`rewrite_holders`)。基準のときの持ち主は、今も持っているか、変わっていて書かれる。
- String は ivar も外への参照も持たないので、新しい String にしても届くものは変わらない。2 か所から持たれる
  String は 2 か所目で名前を付けるので、着いた側で 2 つに分かれない。
- 持ち主のダイジェストに String のバイト列を混ぜるので、String だけを `<<` で変えても持ち主の変化として見える。

### 3.2 費用

数字は `CHECKPOINT_BASELINE_SIZE=1 checkpoint names` (gem が VM ごとに持つバイト数)。

| | 64 bit 表なし | 32 bit 表なし | 32 bit 表あり |
|---|---:|---:|---:|
| 前 (cc664d4、素の mruby) | 117,055 | 99,855 | 23,668 |
| 今 (素の mruby、`CHECKPOINT_NO_FIXTURE=1`) | 117,471 (+416) | 100,219 (+364) | (表がドライバの試験用ライブラリ込みなので測らない。snapshot +13 から約 +120) |
| 今 (試験用ライブラリ `CkBase` 込み) | 127,670 | 108,790 | 26,069 |

- 素の mruby の基準には、名前のあるものから届く名前の無いものが 1 つも無かった (経路の名前 0)。増えたのは
  snapshot 13 個 (メソッドの Env `E:` と `X:` の例外。前は比べていなかった) の分。
- `CkBase` (試験用、ドライバが基準の前に読む。Family mruby の mrblib の代わり) は経路の名前を 68 個作る (うち 40 は
  `BIGKEYS` の鍵の Array)。表ありの 32 bit で `ptrs`・`obj_idx` が 108 個ずつ、slot が 109 個増えた (`CkBase` 自身の
  `V:` の名前とメソッドを含む)。
- Family mruby の見込み: 32 bit 表ありで、経路の名前 1 つあたり約 8 B + 中身のダイジェストを持つものは 9 B。
  `GM_NAMES` のような String の配列の要素には名前を付けないので 0 B (String に名前を付けていれば 1 つ 17 B)。
  ff.md の数 (`keep` 3,016 個、名前のあるオブジェクト約 1,700 個) から、名前の無い基準のものは多くて約 1,300 個
  で、そのうち名前のあるものから届き String でないものだけが増える。実測は pin を進めたあと、Family mruby の
  VM を開くたびのログ (`mrb_checkpoint_baseline_size`) で確認する。
- VM を開く時間 (`checkpoint names` 100 回の平均、64 bit): 前 1.64〜1.76 ms、今 (素) 1.68〜1.70 ms で差は揺れの
  内。`CkBase` 込みで 1.95 ms。
- 書く時間: 入れ物のダイジェストが String の中身も読むようになった分と、特異クラスを見るために名前を一度
  回る分が増える。名前の無い String を運んだときだけ、名前を回って持ち主を探す。fuzz の 2,837 枚の
  イメージは前と同じに書けた。

### 3.3 Ff の固定の表との関係

経路の名前もほかの名前と同じく表に入る (名前の塊・snapshot は表に、アドレスと slot は VM に)。表は同じ
gem で作り直す (名前の決まりが変わったので、版 1 の表は「使わない」と判断される)。表の slot の割り当ては、
中身のダイジェストを持つ型 (String・Array・Hash・Struct・Set・Env・Exception・C のデータ・Random) 全部にした。

## 4. 形式の版

- 形式の版は 1 のまま。足しただけで、既存の記録の意味は変わらない: 変更表の種類 10 の中身の型に 7・13・17・18
  を、変更の種類 11 を足した。古い読み込み側は理由つきで断る (前の gem は `TBL0` の名前の決まりの版で
  `the image names its permanent objects by the rules of table version 2` と断る。SabiRuby は知らない型・種類・
  名前で断る、6 章)。
- 名前の決まりの版 (`MRB_CHECKPOINT_TABLE_VERSION`、`TBL0` に書く) は 1 → 2 に上げた。名前を足しただけで、既存の
  名前が別のものを指すことは無いが、版 1 の書く側は名前の無いものへの変更を黙って落とすので、版 1 のイメージを
  版 2 の読む側で受けると落ちた変更に気づけない。版を上げて、混ざったら理由をつけて断る形にした。表の slot の
  割り当ても変わったので、版 1 の表は使えない (使わずに自分で持つ)。

## 5. 試験

- ドライバ (`tools/checkpoint/checkpoint.c`) が、どの状態でも基準の前に小さなライブラリ `CkBase` を読む
  (Family mruby の mrblib の代わり。`CHECKPOINT_NO_FIXTURE` で外せる、測るため)。
- `test/samples/unnamed_baseline.rb`: 2.2 の 1・3〜18・20 を変えてから止め、続きで全部を表示し、ローカルが持つものが
  定数の中と同じか (`equal?`) を見る。続きでもう一度変えて止める (着いた側の変更がまた運ばれる)。
- `test/samples/unnamed_replace.rb`: 2・19 (差し替え、移す、入れ替え、取り出す、鍵の String を別の Hash のキーに)。
- `test/samples/unnamed_refuse.rb`: 21・22 が理由つきで断られ、イメージを書かない。
- いずれも run_tests の全部の組み合わせ (64・32 の往復、同じプロセス、Task として、表あり・表なしの混ぜ) で
  往復なしと同じ出力。`tools/test_table.rb` の「別の版の表の決まりを断る」は、版 2 を固定で書いていたのを
  「今の版 + 1」にした。
- インスペクタ (`tools/lib`) は新しい中身の型と種類 11 を読む (`contents ... struct [...]`、`singleton class ...`)。

## 6. SabiRuby への影響 (SabiRuby は直していない)

- 経路の名前 (`V:...@X/...`) を引けない (`'V:CkBase@STRINGS/{"en"}' does not exist here` の形で断る)。対応するなら
  `names.rs` に §8.2 の一歩の読み方を足す。
- 変更表の種類 10 の型 7・13・17・18 と種類 11 を知らない (`bad contents type` / `bad change kind` で断る)。Hash の
  中身 (型 5) はもともと未対応。
- 名前の無い String を運ぶ場合は普通の String の記録なので読めるが、持ち主の書き直しが Hash なら上の未対応で断る。
- これらに当たらないイメージは前と同じ。新しい試料 2 つには `sabiruby-refuse` の注記を付けた (文言 `contents`)。
  SabiRuby の手元のビルドが無く、SabiRuby での実行は確認していない。

## 7. Family mruby で確認する形

- 直す前の `FmrbI18n` (70964cb8 の前): `STRINGS = { "en" => {}, "ja" => {} }` を定数に持ち、アプリが
  `FmrbI18n.add("en" => { ckpt_word: "word-en" }, "ja" => { ckpt_word: "word-ja" })` で語を足して移す。着いた側で
  `FmrbI18n.t(:ckpt_word)` が `"word-ja"` (着いた側の言語) を返せば直っている (前は `"ckpt_word"`)。
- 同じ形の試し: 運べるアプリで、基準からある定数の中を変える (`FmrbConst` などの Hash の中の Hash に足す、定数の
  Array の中の String を `<<`)、その中のものをローカルに持ってから移す。`ruby tools/checkpoint_inspect.rb x.ckpt` で
  `contents V:FmrbI18n@STRINGS/{"en"} ...` の行が出る。
- 表: Family mruby の表は gem の版で作り直される (`TBL0` の名前の決まりの版が 2)。ログの
  `mrb_checkpoint_baseline_size` の行で、`ptrs`・`obj_idx`・`slots` の増え方を前と比べる。
