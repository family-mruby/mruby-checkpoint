# 実装指示書 P4b: P4 の残り (時間の割り当て、失われる Task.pass、mrblib の行番号)

`doc/plan.md` (親の仮決め)、`doc/format_v1.md`、`doc/report/p4.md` を先に読む。

## 親の仮決め (2026-11-03、ユーザがあとで見直す)

判断の方針 (楽をせず本質的な対応) により、P4 の「決めてほしいこと」1・4 を次のように決める。

1. **走っていた Task の時間の割り当ては、残りを運ぶのを既定にする** (P4 の指示書の「満タンから」を
   取り消す)。同じ像から何度復元しても同じ動きになる、という「残りの tick」と同じ考え方。
   `mrb_checkpoint_keep_timeslice` の切り替えは、満タンから始めたい埋め込む側のために残すか、
   要らなければ消す (どちらにしたかを report に)。
2. **外からの要求と `Task.pass` が重なって pass が失われる穴を、根本から塞ぐ**。原因は、スケジューラの
   切り替えの頼みが VM の 1 つの bool (`task.switching`) に相乗りしていて、誰が立てたかが残らない
   こと。命令の境目ごとの費用を増やさずに、スケジューラの側が「切り替えを頼んだ」ことを自分で記録する
   形にする。候補 (サブが比べて選ぶ):
   - mruby-task の、切り替えを頼む所 (pass・sleep・時間の割り当ての終わり・起こす・優先度など) で、
     頼みの回数 (または理由) を mruby-task の状態に数える patch (`patches/` に mruby-task 用を足す。
     `vm.c` の patch は変えない)。checkpoint は要求を立てたときの回数と安全点での回数を比べる。
   - 様子の差での見分け (P4 の今の作り) は、この記録で置き換えられるなら消す (2 つの仕組みを残さない)。
   `vm.c` の patch を変える必要が出たら、valgrind の命令数で前後を比べる。
3. **mrblib の枠の行番号**: `DBG0` に、運ぶ mrblib の irep の行の表も入れる (P5 で全部の枠に
   `file:line` を出すため)。形式は変えず、書く側を広げる。SabiRuby の読み手も同じに。

P4 の決めてほしいこと 2 (着いた先の時計を書いたときの tick にする) と 5 (SabiRuby の試験の像
約 240 KB) は、親の仮決めでそのまま認める。3 (上流の不具合 U1〜U5 の報告) は外へ出すことなので
ユーザに残す。

## 試験

- `--quantum` の試験 (種 1〜5、両方の起動の形) が、既定の設定のまま食い違い 0。
- 穴を塞いだことを示す試験: 外からの要求のすぐ次の命令が `Task.pass` になる点を、試験の道具で
  狙って作り (`--at` か専用のサンプル)、P4 の作りでは pass が失われ、P4b では往復なしと同じになる
  ことを示す。試験の道具の `mrb_checkpoint_request_here` は、塞いだあとも要るかを見直し、要らなければ
  P3 と同じ「次の境目で書く」に戻して長い版を流す (要るなら理由を report に)。
- mrblib の枠を含む像で、`tools/checkpoint_inspect.rb` か復元後のバックトレースに mrblib の行が出る。
- `rake test` (SabiRuby あり)、`test:asan`、`test:stress`、cargo test (feature の有無)、長い版の
  fuzz (20 の種、両方の起動の形) が通り、食い違い 0。

## 触ってよい範囲・止まる条件・守ること

- P4 と同じ。mruby-task に patch を足すのはこの段では認める (スケジューラの列・優先度の決め方は
  変えない。変える必要が出たら止まる)。mruby-task の利用者から見た動きを変える必要が出たら止まる。
- report は `doc/report/p4b.md`: 塞ぎ方の比較と選んだ理由、費用 (命令数)、試験の数字。
