# 実装指示書 P5: 像の可視化 (共通の読み手、CLI、HTML)

`doc/plan.md`、`doc/format_v1.md`、`doc/report/p3.md`・`p4.md`・`p4b.md` を先に読む。P4b で `DBG0` は mrblib の irep の行も
持つようになり、`tools/checkpoint_inspect.rb` は全部の枠に `file:line` を出す。

## なぜ要るか (2026-11-03 ユーザ)

像の中身 (どこで止まったか、何を持っているか、2 つの像で何が変わったか) を人が読めるように
する。デモ (Ghost) で見せる材料にもなり、運び方の不具合を調べる道具にもなる。GUI (Asterism の
console か端末のアプリか) は P5 のあとで決めるので、P5 の出力はそのどちらからも使える形にする。

## 決まったこと (2026-11-03 ユーザ)

- 読み手は 1 つ (像 → JSON)。CLI と HTML はその JSON の上に作る。
- CLI は `inspect --stack` と `diff`。HTML は 1 ファイル (外の資源を読まない)。
- 見せるもの 4 つ: 呼び出しの枠 (ファイル名・行・メソッド・局所変数)、オブジェクトの
  つながり、2 つの像の差、Task と Fiber (状態・列・待ちの理由・残り tick)。

## 親の仮決め (ユーザがあとで見直す)

- 読み手は Ruby で書く (`tools/` の他の道具と揃え、周辺の道具は Ruby の方針)。既存の
  `tools/checkpoint_inspect.rb` を土台に、ライブラリ (`tools/lib/checkpoint_image.rb` など)
  と CLI に分ける。C の側に読み手は作らない (像の形の正は `doc/format_v1.md` で、読み手が
  2 つになると食い違う)。
- JSON の形は `doc/inspect_json.md` に書く (GUI の側がこれだけ読めば作れること)。版の欄を持つ。
- HTML は JSON を埋め込んだ 1 ファイルを CLI が書き出す (`inspect --html out.html`)。図は
  素の SVG と JavaScript で描き、外部のライブラリを使わない (端末のブラウザでも開けるように)。
- オブジェクトのつながりは全部描かない。既定は、生きている枠と Task から辿れる範囲を
  深さで切って描き、利用者が辿って開く。permanent (基準) のものは名前だけの印にする。
- 差 (`diff`) は、オブジェクトの番号でなく、根 (枠・Task・グローバル・定数) からの道筋で
  対応を取る (像ごとに番号は振り直されるため)。対応の付け方の限界は文書に書く。

## やること

1. **読み手** (`tools/lib/`): v1 の全ての節を読み、JSON にする。知らない節は中身を 16 進の
   要約にして落とさない。壊れた像はどこで壊れたかを出して止まる。
2. **CLI** (`tools/checkpoint_inspect.rb`、またはドライバの `checkpoint inspect` から呼ぶ形):
   - `--json`: JSON をそのまま出す。
   - `--stack`: Task・Fiber ごとに呼び出しの枠を、バックトレースと同じ並びで出す
     (`file:line:in method`、局所変数の名前と値の短い表示)。
   - `--objects [--depth N]`: つながりを文字で出す。
   - `diff a.ckpt b.ckpt`: 枠の違い、変わった値、増えた/消えたオブジェクト、Task の状態の
     違い。
   - `--html out.html`: 4 つを見られる 1 ファイル。
3. **試験**: `rake test` に入れる。
   - P4 までのサンプルの像全部 (64・32 bit) を読めること、JSON の形の検査。
   - `--stack` の出力が、同じ点で起こした例外のバックトレースと一致すること (行番号の正しさ)。
   - `diff` で、同じ像同士は差なし、`save` を 2 回したものは期待した差だけ。
   - HTML が書き出せ、埋め込んだ JSON が読み戻せること (画面の見た目はヘッドレスの
     ブラウザが使えるなら撮って report に貼る。無ければ構造の検査まで)。
4. 文書: `doc/inspect_json.md`、README の使い方。

## 触ってよい範囲・止まる条件・守ること

- P4 の指示書と同じ (判断の方針も同じ)。サブは自分で選んだことを「サブの仮決め」として report に書く。C の側と SabiRuby は原則触らない (像の形を変える
  必要が出たら止まる)。
- report は `doc/report/p5.md`: 見せ方の判断、大きい像での速さと大きさ (HTML の重さ)、
  GUI に進むときに要るもの。
