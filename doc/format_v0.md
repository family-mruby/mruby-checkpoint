# ghost 形式 v0

> 状態: P1 で実装済 (mruby 側の書き出しと復元) | 更新: 2026-11-02

mruby の VM で動いているプログラムの状態 (ヒープ・呼び出しの枠・VM スタック) を、
別の `mrb_state`・別のプロセス・別のポインタ幅・別の VM 実装で続きから動かすための
形式。C の構造体の写しではなく、mruby の意味論の層で定める。この文書だけを読んで
復元側 (たとえば SabiRuby) を書けることを目標にする。

## 1. 考え方

- **論理グラフ**。オブジェクトに 1 から通し番号を振り、参照は番号で書く。
  ポインタは書かない。
- **普段の実行では何もしない**。書き出す瞬間に、実行中の内部表現 (ポインタ・
  シンボル ID・irep) を名前・番号・内容のハッシュに置き換える。
- **permanent** (= 書き出し側で VM を開いた直後に既にあったもの。組み込みの
  クラス・モジュール・mrblib のメソッドなど) は中身を運ばず**名前**で運び、
  読む側の同じ名前のものに結びつける。運ぶのはプログラムが作ったものと、
  permanent なクラス・オブジェクトへの変更分。
- 値の表現は固定: Integer は 64 bit 符号つき、Float は IEEE 754 倍精度、
  String はバイト列 (UTF-8 として扱う)。ポインタ幅に依らない。

## 2. 基本の符号化

- 整数はすべて**ビッグエンディアン**。`u8` `u16` `u32` `u64`。符号つきは 2 の補数。
- `str` = `u32` の長さ + その長さのバイト列 (終端の 0 は無い)。
- `ref` = `u32`。0 は「無し」(C の NULL、Ruby の nil ではない)。1 以上は表の番号。
  シンボル・irep・オブジェクトはそれぞれ別の表で、番号も別。
- `sym` = シンボル表への `ref`。

## 3. 全体の並び

| 順 | 中身 |
|---|---|
| 1 | ヘッダ |
| 2 | シンボル表: `u32` 個数 + 各 `str` (名前)。番号は出てきた順に 1, 2, ... |
| 3 | irep 表: `u32` 個数 + 各 irep レコード (§6) |
| 4 | オブジェクト表: `u32` 個数 + 各オブジェクトレコード (§7) |
| 5 | 変更表: `u32` 個数 + 各変更レコード (§9) |
| 6 | VM: スタックと呼び出しの枠 (§10) |

ファイルの終わりは VM の部分の終わりと一致する (余りがあれば壊れているとみなす)。

### ヘッダ

| 型 | 中身 |
|---|---|
| 4 バイト | `MRGH` |
| `u16` | 形式の版 = 0 |
| `str` | 書いた処理系の版 (例 `mruby 4.0.0`) |
| `str` | バイトコードの版 = `RITE0400` |
| `u8` | Integer のビット数 = 64 |
| `u8` | Float のビット数 = 64 |
| `u8` | String が UTF-8 なら 1 |
| `u8` | 書いた側のポインタ幅 (情報のみ。読む側は使わない) |

読む側は版と値の表現 (64 / 64 / 1) が合わなければ断る。64bit 版と 32bit 版の
mruby が書くファイルは、最後の 1 バイト以外同一になる。

## 4. 値

`値` = タグ `u8` + 中身。

| タグ | 意味 | 中身 |
|---|---|---|
| 0 | nil | なし |
| 1 | false | なし |
| 2 | true | なし |
| 3 | Integer | `u64` (int64) |
| 4 | Float | `u64` (IEEE 754 倍精度のビット列) |
| 5 | Symbol | `sym` |
| 6 | オブジェクト | オブジェクト表への `ref` (0 は来ない) |
| 7 | undef (VM 内部の「値なし」。レジスタの中にだけ現れうる) | なし |

64 bit に収まらない Integer (mruby-bigint のオブジェクト) は v0 では運ばない (§11)。

## 5. シンボル

シンボルは名前で運ぶ。読む側は名前から自分のシンボルを引く (無ければ作る)。
シンボル ID の数値は処理系・プロセスごとに違ってよい。

## 6. irep (コードの塊)

irep はメソッド・ブロック・トップレベルのコード 1 つ分。**内容のハッシュ**で
識別する (§6.3)。レコードは 2 種類。

### 6.1 permanent な irep

| 型 | 中身 |
|---|---|
| `u8` | 1 |
| `u64` | 内容のハッシュ |

読む側の permanent なメソッド (§8 の `M:` の Proc) の irep と、その子孫の irep の
中から、同じハッシュのものを使う。見つからなければ復元を断る (mrblib の中身が
違う = 枠の命令位置が合わない)。

### 6.2 運ぶ irep

| 型 | 中身 |
|---|---|
| `u8` | 0 |
| `u64` | 内容のハッシュ (読む側は組み立て後に計算し直して照合する) |
| `u16` | nlocals: 局所変数の数 (self を含む) |
| `u16` | nregs: 使うレジスタの数 |
| `u16` | clen: 例外処理の表の行数 |
| `u32` | ilen: 命令列のバイト数 |
| バイト列 | 命令列 ilen バイト + 例外処理の表 13×clen バイト |
| `u16` | plen: 定数プールの個数 |
| 各プール | 種類 `u8` + 中身: 0 = 文字列 `str` / 1 = 整数 `u64` (int64) / 2 = 浮動小数 `u64` (ビット列) / 3 = 多倍長整数 `str` (mruby の内部の詰め方そのまま。v0 では不透明) |
| `u16` | slen: シンボルの個数 |
| 各 `sym` | 命令が使うシンボル (0 は「無し」) |
| `u16` | rlen: 子の irep の個数 |
| 各 `ref` | 子の irep (irep 表の番号。0 は無し) |
| `u16` | 局所変数名の個数 (nlocals − 1 か 0) |
| 各 `sym` | 局所変数名 (R1 から順。0 は無名) |

- 命令列は mruby 4.0 のバイトコード (RITE 04.00 の命令表。`OP_EXT1..3` を含む) で、
  `.mrb` ファイルの IREP の命令列と同じ。オペランドのシンボル・プール・子 irep の
  番号は、この irep の中の表の添字 (0 起点)。
- 例外処理の表の 1 行は 13 バイト: 種類 `u8` (0 = rescue, 1 = ensure)、開始 `u32`、
  終了 `u32` (含まない)、飛び先 `u32`。いずれも命令列の中のバイト位置。
- 行番号などのデバッグ情報は v0 では運ばない (§12)。

### 6.3 内容のハッシュ

FNV-1a 64 bit (初期値 `0xcbf29ce484222325`、乗数 `0x100000001b3`、1 バイトずつ
xor してから掛ける)。下の順にバイト列を流す。`U(x)` は x を `u64` のビッグエンディアン
8 バイトにしたもの。

1. `U(nlocals)` `U(nregs)` `U(clen)` `U(ilen)`
2. 命令列 + 例外処理の表 (ilen + 13×clen バイト)
3. `U(plen)`、各プール: 整数 `U('i')` `U(値)` / 浮動小数 `U('f')` `U(ビット列)` /
   多倍長 `U('b')` `U(長さ)` バイト列 / 文字列 `U('s')` `U(長さ)` バイト列
   (`'i'` などは文字コードの数値)
4. `U(slen)`、各シンボル: 無しなら `U(0xffffffffffffffff)`、あれば `U(名前の長さ)` + 名前
5. `U(rlen)`、各子: 子のハッシュ (無しなら 0) を `U()` で

局所変数名とデバッグ情報はハッシュに入れない。

## 7. オブジェクト

表の i 番目のレコードがオブジェクト i。参照は前にも後ろにも向いてよい (循環あり)。
読む側は 2 回なめる: 1 回目で全部の器を作り (permanent は名前で引く)、2 回目で
中身を埋める。

レコードの先頭は種類 `u8`。permanent 以外は続けて共通の頭を持つ:

| 型 | 中身 |
|---|---|
| `ref` | クラス (そのオブジェクトの `class` が指すもの。特異クラスがあればそれ) |
| `u8` | frozen なら 1 |

### 種類ごとの中身

| 種類 | 名前 | 共通の頭の後 |
|---|---|---|
| 1 | permanent | (共通の頭なし) `str` 名前 (§8) |
| 2 | Object | ivar の並び |
| 3 | String | `str` 中身 |
| 4 | Array | `u32` 個数 + 各 `値` |
| 5 | Hash | `u8` 既定値の印 (bit0 = 既定値あり、bit1 = 既定値は Proc) + `u32` 組数 + 各 (`値` 鍵, `値` 値) + ivar の並び |
| 6 | Range | `値` 始め, `値` 終わり, `u8` 終わりを含まないなら 1 |
| 7 | Exception | `値` メッセージ (nil か String), `値` バックトレース (nil か String の Array) + ivar の並び |
| 8 | Class | クラスの中身 (下) |
| 9 | Module | クラスの中身 |
| 10 | 特異クラス | クラスの中身 |
| 11 | 取り込みクラス | `ref` 上位 (共通の頭のクラスは、取り込んだモジュール) |
| 12 | Proc | Proc の中身 (下) |
| 13 | Env | Env の中身 (下) |
| 14 | C のデータ | `str` 型の名前 + `str` 中身 (型ごとの関数が書いたバイト列) + ivar の並び |

**ivar の並び** = `u32` 個数 + 各 (`sym` 名前, `値`)。並びの順に入れる (順序を保つ)。
クラスの「ivar」には定数・クラス変数 (`@@x`) と、処理系の内部の印 (`__classname__`
= 名前のシンボル、`__outer__` = 外側のクラス、`__attached__` = 特異クラスの持ち主)
も入る。Hash の既定値・既定の Proc は ivar `ifnone` として入る。

**Hash の鍵**は、読む側で全部のオブジェクトとメソッドがそろってから入れ直す
(鍵のハッシュ値は読む側で計算し直す。`hash` / `eql?` が利用者のメソッドでもよい)。
並び順が挿入順になる。

**クラスの中身** (8, 9, 10):

| 型 | 中身 |
|---|---|
| `ref` | 上位 (superclass。取り込みクラスを挟むことがある。0 は BasicObject の上) |
| `u8` | インスタンスの種類: 0 = 未指定 (上位に従う)、1 = Object、2 = Exception、3 = String、4 = Array、5 = Hash、6 = Range、7 = Proc、8 = C のデータ |
| `u8` | bit0 = allocate 禁止、bit1 = 継承済みの印 (メソッドキャッシュの手がかり。無視してよい) |
| ivar の並び | |
| `u32` | メソッドの数 |
| 各メソッド | `sym` 名前、`u8` 可視性 (0 public, 1 private, 2 protected)、`u8` 種類 + 中身: 0 = Proc (`ref`)、1 = C の関数 (`str` 名前 (§8 の `F:`) + `u32` 引数の仕様 (mruby の aspec))、2 = undef (このクラスで未定義にした) |

**Proc の中身**:

| 型 | 中身 |
|---|---|
| `u8` | bit0 = lambda、bit1 = orphan (return の行き先がもう無い)、bit2 = scope (メソッドの本体。return はここで止まる) |
| `u8` | 本体の種類: 0 = irep、1 = C の関数 |
| | 0 なら `ref` irep / 1 なら `str` 関数の名前 + `u32` 引数の仕様 (最上位ビットが立っていれば下位 31 bit が aspec、0 なら引数なし) |
| `ref` | 外側の Proc (ブロックが書かれたメソッド・ブロック。無ければ 0) |
| `u8` | 環境の種類: 0 = 無し、1 = Env、2 = 定義先のクラス |
| `ref` | その Env かクラス |

**Env の中身** (ブロック・クロージャが捕まえた局所変数の箱):

| 型 | 中身 |
|---|---|
| (共通の頭のクラス) | 定義先のクラス (target class) |
| `sym` | その枠のメソッド名 |
| `u8` | 長さ (変数の数。R0 = self を含む) |
| `u8` | ブロック引数のレジスタ番号 |
| `u8` | 可視性の印 (bit0-1 = 既定の可視性、bit2 = 可視性の区切り、bit3 = module_function 中) |
| `u8` | 1 = スタック上 / 0 = 切り離し済み |
| | スタック上なら `u32` スタックの位置 / 切り離し済みなら 長さ ぶんの `値` |

- **スタック上の Env** は、まだ動いている枠のレジスタそのものを指している (枠の
  レジスタとクロージャから見える変数は同じ場所)。位置は §10 のスタック配列の添字で、
  必ずどれかの枠の R0 の位置に一致し、その枠の「環境」(§10) がこの Env を指す。
  読む側は Env の中身を別に持たず、スタックを共有させること。
- **切り離し済みの Env** は、枠が終わった後のクロージャの変数 (値を自分で持つ)。

## 8. permanent の名前

書く側と読む側は、どちらも VM を開いた直後 (プログラムを読む前) の状態を同じ
手順でなめて、permanent なものに名前を付ける。名前が同じなら同じものとみなす。

| 形 | 指すもの |
|---|---|
| `T` | トップレベルの self (main) |
| `Object`, `Comparable`, `Math::DomainError` | 定数の道筋で届くクラス・モジュール (Object の直下は `Object::` を付けない) |
| `S:<名前>` | `<名前>` の特異クラス (`S:T` は main の特異クラス) |
| `I:<名前>/<k>` | `<名前>` の直上に並ぶ k 番目 (0 起点) の取り込みクラス |
| `M:<名前>#<メソッド>` | そのクラスのメソッドの Proc (mrblib で Ruby で書かれたものなど) |
| `E:<名前>#<メソッド>` | その Proc の Env |
| `F:<名前>#<メソッド>` | メソッド表にある C の関数 |
| `F:attr_reader`, `F:attr_writer` | attr_reader / attr_writer が作るクロージャの C の関数 |
| `V:<名前>@<ivar か定数>` | クラスの ivar・定数が持つオブジェクト |
| `G:$<名前>` | 大域変数が持つオブジェクト |
| `X:nomem_err`, `X:stack_err` | 処理系が前もって作っておく例外 |

なめ方: `F:attr_*` → `T` → `Object` から深さ優先 → `S:T` → 大域変数 → 前もって作る
例外。1 つのクラスでは、メソッド (名前順) → 直上の取り込みクラス → 特異クラス →
ivar と定数 (名前順。クラス・モジュールを指す定数はそこで深さ優先に下る)。
最初に付いた名前を使い、同じものに二度は付けない。名前順はシンボル名のバイト順。

v0 の mruby 側は「同じビルドなら同じ名前」で十分だが、別の処理系 (SabiRuby) が
読むには、相手の組み込みに同じ名前を付ける対応表が要る (P2)。

## 9. 変更表

permanent なものへの変更を、読む側の permanent なものに当てる。各レコードは
種類 `u8` で始まる。対象 (`ref`) は permanent のオブジェクト。

| 種類 | 名前 | 中身 |
|---|---|---|
| 1 | メソッドの定義 | `ref` クラス + メソッド 1 つ (§7 のクラスの中身と同じ形) |
| 2 | メソッドの削除 | `ref` クラス + `sym` |
| 3 | ivar・定数の設定 | `ref` オブジェクト + `sym` + `値` |
| 4 | ivar・定数の削除 | `ref` オブジェクト + `sym` |
| 5 | 上位の付け替え | `ref` クラス + `ref` 新しい上位 (permanent なクラスへの include) |
| 6 | 大域変数の設定 | `sym` + `値` |
| 7 | 大域変数の削除 | `sym` |

プログラムが定義したトップレベルのクラスは「Object への定数の設定」として現れ、
トップレベルの `def` は「Object へのメソッドの定義」(private) として現れる。

## 10. VM

ルートの文脈 (Fiber でも Task でもない、プログラムの本体) の状態。

| 型 | 中身 |
|---|---|
| `u32` | スタックの長さ L |
| L 個の `値` | スタック配列 (レジスタの並び) |
| `u32` | 枠の数 N (1 以上) |
| N 個の枠 | 下 (一番外 = トップレベル) から上 (いま動いている枠) の順 |

**枠** (呼び出し 1 つ分。mruby の callinfo):

| 型 | 中身 |
|---|---|
| `sym` | メソッド名 (トップレベルやブロックでは 0 のことがある) |
| `ref` | 動いている Proc (irep を持つもの。C の関数の枠は v0 では来ない) |
| `u32` | レジスタの窓の始まり = この枠の R0 のスタック上の位置 |
| `u32` | pc = Proc の irep の命令列の中のバイト位置 (`0xffffffff` は無し) |
| `u8` | 位置引数の数 (15 = 1 つの Array に詰めて渡した) |
| `u8` | キーワード引数の数 (15 = 1 つの Hash に詰めて渡した) |
| `u8` | C から呼ばれた印 (v0 では常に 0) |
| `u8` | 可視性の印 (Env と同じ意味の 4 bit) |
| `ref` | 渡されたブロック (Proc。無ければ 0) |
| `u8` + `ref` | 環境: 0 = 無し / 1 = Env / 2 = 定義先のクラス |

- **レジスタの窓**: 枠 k の Ri はスタック配列の [始まり + i]。呼ばれた側の R0
  (self) は呼んだ側の R[a] と同じ場所 (a = 呼ばれた側の始まり − 呼んだ側の始まり)。
  呼ばれた側が戻ると戻り値はそこに入る。
- **pc**: いちばん上の枠では「次に実行する命令」の位置。それより下の枠では
  「呼び出しから戻ったら実行する命令」(呼び出し命令の次) の位置。
- スタックの長さは、いちばん上の枠の始まり + その irep の nregs (と引数の分の
  大きい方)。それより上は nil とみなす。
- 続きから動かすには、スタックと枠を組み立て、いちばん上の枠の pc から命令の
  実行を始める。いちばん上の枠が戻れば、普通の return と同じく下の枠の pc に
  戻る。いちばん下の枠が戻ればプログラムの終わり。

## 11. 書き出しを断る場合

次のどれかに当たると、書き出し側は理由 (どのオブジェクトの、どの型か、どこから
届いたか) を添えて断る。mruby 側は `Ghost::Error` を上げ、プログラムは続く。

- 運べない型: Fiber、Task、Struct、Set、Complex・Rational、多倍長整数、
  バックトレース以外の内部オブジェクト、C のポインタ値。
- C のデータで、型ごとの dump / restore の別表に登録の無いもの。
- `prepend` を使ったクラス。別名 (alias) を Proc にしたもの。
- VM を開いた直後からあったのに名前の付かないオブジェクト。
- permanent な String / Array / Hash の中身が変わっている (v0 は permanent への
  変更をクラス・ivar・大域変数に限る)。
- Fiber や Task の中にいるとき、Task が残っているとき。

## 12. v0 で決めていないこと

- デバッグ情報 (行番号)。復元後のバックトレースには行番号が出ない。
- Fiber・Task・C のデータの汎用の扱い。
- 形式の圧縮、改ざんの検出、暗号化。
- 処理系をまたぐ permanent の対応表 (P2 で SabiRuby 側に作る)。
