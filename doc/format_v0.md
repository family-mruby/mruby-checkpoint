# checkpoint 形式 v0

> 状態: **v1 で置き換えた** (P4、`doc/format_v1.md`)。この文書は経過として残す | P1 で実装、P1b で改名、P2 で mrblib の irep の中身を運ぶ追補 (§6.4・§7 の種類 15)、P3 で種類とセクションの追補 (§13〜§16) | 更新: 2026-11-03

mruby の VM で動いているプログラムの状態 (ヒープ・フレーム・VM スタック) を、
別の `mrb_state`・別のプロセス・別のポインタ幅・別の VM 実装で続きから動かすための
形式。C の構造体の写しではなく、mruby の意味論の層で定める。この文書だけを読んで
復元側 (たとえば SabiRuby) を書けることを目標にする。

## 1. 考え方

- **論理グラフ**。オブジェクトに 1 から通し番号を振り、参照は番号で書く。
  ポインタは書かない。
- **普段の実行では何もしない**。書き出す瞬間に、実行中の内部表現 (ポインタ・
  シンボル ID・irep) を名前・番号・内容のハッシュに置き換える。
- **permanent** (= 書き出し側で VM を開いた直後に既にあったもの。組み込みの
  クラス・モジュール・mrblib のメソッドなど) は中身を運ばず**名前**で運び、
  読む側の同じ名前のものに結びつける。運ぶのはプログラムが作ったものと、
  permanent なクラス・オブジェクトへの変更分。
- 値の内部表現は固定: Integer は 64 bit 符号つき、Float は IEEE 754 倍精度、
  String はバイト列 (UTF-8 として扱う)。ポインタ幅に依らない。

## 2. 基本の符号化

- 整数はすべて**ビッグエンディアン**。`u8` `u16` `u32` `u64`。符号つきは 2 の補数。
- `str` = `u32` の長さ + その長さのバイト列 (終端の 0 は無い)。
- `ref` = `u32`。0 は「無し」(C の NULL、Ruby の nil ではない)。1 以上は表の番号。
  シンボル・irep・オブジェクトはそれぞれ別の表で、番号も別。
- `sym` = シンボル表への `ref`。

## 3. 全体の並び

| 順 | 中身 |
|---|---|
| 1 | ヘッダ |
| 2 | シンボル表: `u32` 個数 + 各 `str` (名前)。番号は出てきた順に 1, 2, ... |
| 3 | irep 表: `u32` 個数 + 各 irep レコード (§6) |
| 4 | オブジェクト表: `u32` 個数 + 各オブジェクトレコード (§7) |
| 5 | 変更表: `u32` 個数 + 各変更レコード (§9) |
| 6 | VM: スタックとフレーム (§10) |
| 7 | 任意のセクション (§14。タグ 4 バイト + 中身、0 個以上) |
| 8 | 終端タグ `END0` (§14) |

ファイルの終わりは `END0` の終わりと一致する (余りがあれば壊れているとみなす。`END0` が
無ければ途中で切れているとみなす。P3 から)。

### ヘッダ

| 型 | 中身 |
|---|---|
| 4 バイト | `MRCK` |
| `u16` | 形式の版 = 0 |
| `str` | 書いた処理系の版 (例 `mruby 4.0.0`) |
| `str` | バイトコードの版 = `RITE0400` |
| `u8` | Integer のビット数 = 64 |
| `u8` | Float のビット数 = 64 |
| `u8` | String が UTF-8 なら 1 |
| `u8` | 書いた側のポインタ幅 (情報のみ。読む側は使わない) |

読む側は版と値の内部表現 (64 / 64 / 1) が合わなければ断る。64bit 版と 32bit 版の
mruby が書くファイルは、最後の 1 バイト以外同一になる。

## 4. 値

`値` = タグ `u8` + 中身。

| タグ | 意味 | 中身 |
|---|---|---|
| 0 | nil | なし |
| 1 | false | なし |
| 2 | true | なし |
| 3 | Integer | `u64` (int64) |
| 4 | Float | `u64` (IEEE 754 倍精度のビット列) |
| 5 | Symbol | `sym` |
| 6 | オブジェクト | オブジェクト表への `ref` (0 は来ない) |
| 7 | undef (VM 内部の「値なし」。レジスタの中にだけ現れうる) | なし |

64 bit に収まらない Integer (mruby-bigint のオブジェクト) は v0 では運ばない (§11)。

## 5. シンボル

シンボルは名前で運ぶ。読む側は名前から自分のシンボルを引く (無ければ作る)。
シンボル ID の数値は処理系・プロセスごとに違ってよい。

## 6. irep (コードの塊)

irep はメソッド・ブロック・トップレベルのコード 1 つ分。**内容のハッシュ**で
識別する (§6.3)。レコードは 3 種類 (先頭の `u8`: 0 = 運ぶ、1 = permanent、
2 = permanent で中身も運ぶ)。

### 6.1 permanent な irep

| 型 | 中身 |
|---|---|
| `u8` | 1 |
| `u64` | 内容のハッシュ |

読む側の permanent なメソッド (§8 の `M:` の Proc) の irep と、その子孫の irep の
中から、同じハッシュのものを使う。見つからなければ復元を断る (mrblib の中身が
違う = フレームの命令位置が合わない)。

### 6.2 運ぶ irep

| 型 | 中身 |
|---|---|
| `u8` | 0 |
| `u64` | 内容のハッシュ (読む側は組み立て後に計算し直して照合する) |
| `u16` | nlocals: ローカル変数の数 (self を含む) |
| `u16` | nregs: 使うレジスタの数 |
| `u16` | clen: 例外処理の表の行数 |
| `u32` | ilen: 命令列のバイト数 |
| バイト列 | 命令列 ilen バイト + 例外処理の表 13×clen バイト |
| `u16` | plen: 定数プールの個数 |
| 各プール | 種類 `u8` + 中身: 0 = 文字列 `str` / 1 = 整数 `u64` (int64) / 2 = 浮動小数 `u64` (ビット列) / 3 = 多倍長整数 `str` (mruby の内部の詰め方そのまま。v0 では不透明) |
| `u16` | slen: シンボルの個数 |
| 各 `sym` | 命令が使うシンボル (0 は「無し」) |
| `u16` | rlen: 子の irep の個数 |
| 各 `ref` | 子の irep (irep 表の番号。0 は無し) |
| `u16` | ローカル変数名の個数 (nlocals − 1 か 0) |
| 各 `sym` | ローカル変数名 (R1 から順。0 は無名) |

- 命令列は mruby 4.0 のバイトコード (RITE 04.00 の命令表。`OP_EXT1..3` を含む) で、
  `.mrb` ファイルの IREP の命令列と同じ。オペランドのシンボル・プール・子 irep の
  番号は、この irep の中の表の添字 (0 起点)。
- 例外処理の表の 1 行は 13 バイト: 種類 `u8` (0 = rescue, 1 = ensure)、開始 `u32`、
  終了 `u32` (含まない)、飛び先 `u32`。いずれも命令列の中のバイト位置。
- 行番号などのデバッグ情報は v0 では運ばない (§12)。

### 6.3 内容のハッシュ

FNV-1a 64 bit (初期値 `0xcbf29ce484222325`、乗数 `0x100000001b3`、1 バイトずつ
xor してから掛ける)。下の順にバイト列を流す。`U(x)` は x を `u64` のビッグエンディアン
8 バイトにしたもの。

1. `U(nlocals)` `U(nregs)` `U(clen)` `U(ilen)`
2. 命令列 + 例外処理の表 (ilen + 13×clen バイト)
3. `U(plen)`、各プール: 整数 `U('i')` `U(値)` / 浮動小数 `U('f')` `U(ビット列)` /
   多倍長 `U('b')` `U(長さ)` バイト列 / 文字列 `U('s')` `U(長さ)` バイト列
   (`'i'` などは文字コードの数値)
4. `U(slen)`、各シンボル: 無しなら `U(0xffffffffffffffff)`、あれば `U(名前の長さ)` + 名前
5. `U(rlen)`、各子: 子のハッシュ (無しなら 0) を `U()` で

ローカル変数名とデバッグ情報はハッシュに入れない。

### 6.4 permanent で中身も運ぶ irep (P2 の追補)

| 型 | 中身 |
|---|---|
| `u8` | 2 |
| `u64` | 内容のハッシュ |
| | 以下 §6.2 の nlocals からローカル変数名までと同じ |

- 書く側は、表に入る permanent な irep (mrblib のもの) をすべてこの形で書く。
  permanent な irep が表に入るのは、生きたコードが要るときだけ: フレームが動かしている
  (§7 の種類 15)、実行中に作られた Proc が持っている (mrblib の中のブロック)、
  そのどちらかの子孫。他の mrblib のメソッドは今までどおり名前 (§8) で結ぶ。
- 読む側は、同じハッシュの permanent な irep を自分が持っていればそれを使い
  (同じビルドどうし。中身は読み飛ばす)、無ければ中身から組み立てる (別の版の
  mrblib を持つ処理系。SabiRuby は 4.1.0-rc2 の mrblib を持つので必ずこちら)。
  組み立てたものはハッシュを計算し直して照合する。
- 種類 1 (ハッシュだけ) は P2 からは書かない。読む側は引き続き受け付ける。

## 7. オブジェクト

表の i 番目のレコードがオブジェクト i。参照は前にも後ろにも向いてよい (循環あり)。
読む側は 2 回なめる: 1 回目で全部の器を作り (permanent は名前で引く)、2 回目で
中身を埋める。

レコードの先頭は種類 `u8`。permanent 以外は続けて共通ヘッダを持つ:

| 型 | 中身 |
|---|---|
| `ref` | クラス (そのオブジェクトの `class` が指すもの。特異クラスがあればそれ) |
| `u8` | frozen なら 1 |

### 種類ごとの中身

| 種類 | 名前 | 共通ヘッダの後 |
|---|---|---|
| 1 | permanent | (共通ヘッダなし) `str` 名前 (§8) |
| 2 | Object | ivar の並び |
| 3 | String | `str` 中身 |
| 4 | Array | `u32` 個数 + 各 `値` |
| 5 | Hash | `u8` 既定値のフラグ (bit0 = 既定値あり、bit1 = 既定値は Proc) + `u32` 組数 + 各 (`値` キー, `値` 値) + ivar の並び |
| 6 | Range | `値` 始め, `値` 終わり, `u8` 終わりを含まないなら 1 |
| 7 | Exception | `値` メッセージ (nil か String), `値` バックトレース (nil か String の Array) + ivar の並び |
| 8 | Class | クラスの中身 (下) |
| 9 | Module | クラスの中身 |
| 10 | 特異クラス | クラスの中身 |
| 11 | 取り込みクラス | `ref` スーパークラス (共通ヘッダのクラスは、取り込んだモジュール) |
| 12 | Proc | Proc の中身 (下) |
| 13 | Env | Env の中身 (下) |
| 14 | C のデータ | `str` 型の名前 + `str` 中身 (型ごとの関数が書いたバイト列) + ivar の並び |
| 15 | フレームが動かす permanent な Proc (P2 の追補) | (共通ヘッダなし) `str` 名前 (§8、`M:` の名前) + `ref` irep (§6.4 の種類 2) |

**種類 15** は、いずれかのフレーム (§10) の Proc が mrblib のメソッドの Proc のときに、
種類 1 の代わりに使う。名前で結ぶのは種類 1 と同じだが、その Proc の irep の中身も
表にある。同じビルドの読み込み側は名前で引いた Proc をそのまま使い (irep も自分のもの)、
mrblib の違う読み込み側は、運ばれた irep を本体とする Proc を新しく作ってフレームに使う
(メソッドの持ち主のクラスは名前から、strict と scope は立てる)。その Proc を
`upper` に持つブロックも同じものを指す。

**ivar の並び** = `u32` 個数 + 各 (`sym` 名前, `値`)。並びの順に入れる (順序を保つ)。
クラスの「ivar」には定数・クラス変数 (`@@x`) と、処理系の内部用の変数 (`__classname__`
= 名前のシンボル、`__outer__` = 外側のクラス、`__attached__` = 特異クラスの持ち主)
も入る。Hash の既定値・既定の Proc は ivar `ifnone` として入る。

**Hash のキー**は、読む側で全部のオブジェクトとメソッドがそろってから入れ直す
(キーのハッシュ値は読む側で計算し直す。`hash` / `eql?` が利用者のメソッドでもよい)。
並び順が挿入順になる。

**クラスの中身** (8, 9, 10):

| 型 | 中身 |
|---|---|
| `ref` | スーパークラス (superclass。取り込みクラスを挟むことがある。0 は BasicObject の上) |
| `u8` | インスタンスの種類: 0 = 未指定 (スーパークラスに従う)、1 = Object、2 = Exception、3 = String、4 = Array、5 = Hash、6 = Range、7 = Proc、8 = C のデータ |
| `u8` | bit0 = allocate 禁止、bit1 = 継承済みのフラグ (メソッドキャッシュの手がかり。無視してよい) |
| ivar の並び | |
| `u32` | メソッドの数 |
| 各メソッド | `sym` 名前、`u8` 可視性 (0 public, 1 private, 2 protected)、`u8` 種類 + 中身: 0 = Proc (`ref`)、1 = C の関数 (`str` 名前 (§8 の `F:`) + `u32` 引数の仕様 (mruby の aspec))、2 = undef (このクラスで未定義にした) |

**Proc の中身**:

| 型 | 中身 |
|---|---|
| `u8` | bit0 = lambda、bit1 = orphan (return の行き先がもう無い)、bit2 = scope (メソッドの本体。return はここで止まる) |
| `u8` | 本体の種類: 0 = irep、1 = C の関数 |
| | 0 なら `ref` irep / 1 なら `str` 関数の名前 + `u32` 引数の仕様 (最上位ビットが立っていれば下位 31 bit が aspec、0 なら引数なし) |
| `ref` | 外側の Proc (ブロックが書かれたメソッド・ブロック。無ければ 0) |
| `u8` | 環境の種類: 0 = 無し、1 = Env、2 = 定義先のクラス |
| `ref` | その Env かクラス |

**Env の中身** (ブロック・クロージャが捕まえたローカル変数の箱):

| 型 | 中身 |
|---|---|
| (共通ヘッダのクラス) | 定義先のクラス (target class) |
| `sym` | そのフレームのメソッド名 |
| `u8` | 長さ (変数の数。R0 = self を含む) |
| `u8` | ブロック引数のレジスタ番号 |
| `u8` | 可視性のフラグ (bit0-1 = 既定の可視性、bit2 = 可視性の区切り、bit3 = module_function 中) |
| `u8` | 1 = スタック上 / 0 = 切り離し済み |
| | スタック上なら `u32` スタックの位置 / 切り離し済みなら 長さ ぶんの `値` |

- **スタック上の Env** は、まだ実行中のフレームのレジスタそのものを指している (フレームの
  レジスタとクロージャから見える変数は同じ場所)。位置は §10 のスタック配列の添字で、
  必ずどれかのフレームの R0 の位置に一致し、そのフレームの「環境」(§10) がこの Env を指す。
  読む側は Env の中身を別に持たず、スタックを共有させること。
- **切り離し済みの Env** は、フレームが終わった後のクロージャの変数 (値を自分で持つ)。

## 8. permanent の名前

書く側と読む側は、どちらも VM を開いた直後 (プログラムを読む前) の状態を同じ
手順でなめて、permanent なものに名前を付ける。名前が同じなら同じものとみなす。

| 形 | 指すもの |
|---|---|
| `T` | トップレベルの self (main) |
| `Object`, `Integer`, `Math::DomainError` | クラス・モジュール。そのクラス自身の名前 (`Fixnum` のような別名の定数から届いても `Integer`)。名前の無いものは届いた定数のパス (Object の直下は `Object::` を付けない) |
| `S:<名前>` | `<名前>` の特異クラス (`S:T` は main の特異クラス) |
| `I:<名前>/<k>` | `<名前>` の直上に並ぶ k 番目 (0 起点) の取り込みクラス |
| `M:<名前>#<メソッド>` | そのクラスのメソッドの Proc (mrblib で Ruby で書かれたものなど) |
| `E:<名前>#<メソッド>` | その Proc の Env |
| `F:<名前>#<メソッド>` | メソッド表にある C の関数 |
| `F:attr_reader`, `F:attr_writer` | attr_reader / attr_writer が作るクロージャの C の関数 |
| `V:<名前>@<ivar か定数>` | クラスの ivar・定数が持つオブジェクト |
| `G:$<名前>` | グローバル変数が持つオブジェクト |
| `X:nomem_err`, `X:stack_err` | 処理系が前もって作っておく例外 |

なめ方: `F:attr_*` → `T` → `Object` から深さ優先 → `S:T` → グローバル変数 → 前もって作る
例外。1 つのクラスでは、メソッド (名前順) → 直上の取り込みクラス → 特異クラス →
ivar と定数 (名前順。クラス・モジュールを指す定数はそこで深さ優先に下る)。
最初に付いた名前を使い、同じものに二度は付けない。名前順はシンボル名のバイト順。

v0 の mruby 側は「同じビルドなら同じ名前」で十分だが、別の処理系 (SabiRuby) が
読むには、相手の組み込みに同じ名前を付ける対応表が要る (P2)。

名前の一覧は `checkpoint names` で出る (なめた順に 1 行 1 つ。C 関数は `F:` で
始まる)。SabiRuby は表を持たず、名前を自分のクラスの表をたどって引く (`M:`・`F:` は
そのクラスのメソッド表、無ければ祖先のもの)。C で書かれたメソッド (`F:`) と、
C mruby では Ruby、SabiRuby では Rust のメソッド (`M:`) は、メソッド表の項目と
してはどちらも相手のメソッドに結ぶ。値として Proc そのものが要るときだけ断る。
`F:attr_reader` / `F:attr_writer` の Proc (環境に ivar の名前を持つ) は、SabiRuby の
属性メソッドに置き換える。

## 9. 変更表

permanent なものへの変更を、読む側の permanent なものに当てる。各レコードは
種類 `u8` で始まる。対象 (`ref`) は permanent のオブジェクト。

| 種類 | 名前 | 中身 |
|---|---|---|
| 1 | メソッドの定義 | `ref` クラス + メソッド 1 つ (§7 のクラスの中身と同じ形) |
| 2 | メソッドの削除 | `ref` クラス + `sym` |
| 3 | ivar・定数の設定 | `ref` オブジェクト + `sym` + `値` |
| 4 | ivar・定数の削除 | `ref` オブジェクト + `sym` |
| 5 | スーパークラスの付け替え | `ref` クラス + `ref` 新しいスーパークラス (permanent なクラスへの include) |
| 6 | グローバル変数の設定 | `sym` + `値` |
| 7 | グローバル変数の削除 | `sym` |

プログラムが定義したトップレベルのクラスは「Object への定数の設定」として現れ、
トップレベルの `def` は「Object へのメソッドの定義」(private) として現れる。

## 10. VM

ルートのコンテキスト (Fiber でも Task でもない、プログラムの本体) の状態。

| 型 | 中身 |
|---|---|
| `u32` | スタックの長さ L |
| L 個の `値` | スタック配列 (レジスタの並び) |
| `u32` | フレームの数 N (1 以上) |
| N 個のフレーム | 下 (一番外 = トップレベル) から上 (いま実行中のフレーム) の順 |

**フレーム** (呼び出し 1 つ分。mruby の callinfo):

| 型 | 中身 |
|---|---|
| `sym` | メソッド名 (トップレベルやブロックでは 0 のことがある) |
| `ref` | 実行中の Proc (irep を持つもの。C の関数のフレームは v0 では来ない) |
| `u32` | レジスタの窓の始まり = このフレームの R0 のスタック上の位置 |
| `u32` | pc = Proc の irep の命令列の中のバイト位置 (`0xffffffff` は無し) |
| `u8` | 位置引数の数 (15 = 1 つの Array に詰めて渡した) |
| `u8` | キーワード引数の数 (15 = 1 つの Hash に詰めて渡した) |
| `u8` | C から呼ばれたフラグ (v0 では常に 0) |
| `u8` | 可視性のフラグ (Env と同じ意味の 4 bit) |
| `ref` | 渡されたブロック (Proc。無ければ 0) |
| `u8` + `ref` | 環境: 0 = 無し / 1 = Env / 2 = 定義先のクラス |

- **レジスタの窓**: フレーム k の Ri はスタック配列の [始まり + i]。呼ばれた側の R0
  (self) は呼んだ側の R[a] と同じ場所 (a = 呼ばれた側の始まり − 呼んだ側の始まり)。
  呼ばれた側が戻ると戻り値はそこに入る。
- **pc**: いちばん上のフレームでは「次に実行する命令」の位置。それより下のフレームでは
  「呼び出しから戻ったら実行する命令」(呼び出し命令の次) の位置。
- スタックの長さは、いちばん上のフレームの始まり + その irep の nregs (と引数の分の
  大きい方)。それより上は nil とみなす。
- **死んだレジスタ** (P3): 書く側は、各フレームの命令列から「この先読まれない」と分かる
  一時レジスタ (ローカル変数より上) を nil として書く。値の意味は変わらない (読まれない)。
  読む側は何もしなくてよい。どのレジスタを nil にするかは書く側の判断で、形式の約束
  ではない。
- 書き出しは `Checkpoint.save` / `Checkpoint.suspend` の呼び出し命令が終わった
  直後の境目で行う (外からの要求 (P3) では、要求の後の最初のセーフポイント。その場合はどの
  レジスタも書き換えない)。いちばん上のフレームのその呼び出しの戻り先のレジスタには、
  `resumed` のシンボルが入っている (書いた側のプログラムには `saved` が返る)。
  読む側はそのまま組み立てればよく、特別な扱いは要らない。
- 続きから動かすには、スタックとフレームを組み立て、いちばん上のフレームの pc から命令の
  実行を始める。いちばん上のフレームが戻れば、普通の return と同じく下のフレームの pc に
  戻る。いちばん下のフレームが戻ればプログラムの終わり。

## 11. 書き出しを断る場合

次のどれかに当たると、書き出し側は理由 (どのオブジェクトの、どの型か、どこから
届いたか) を添えて断る。mruby 側は `Checkpoint::Error` を上げ、プログラムは続く。

- 運べない型: Fiber、Task、Struct、Set、Complex・Rational、多倍長整数、
  バックトレース以外の内部オブジェクト、C のポインタ値。
- C のデータで、型ごとの dump / restore の別表に登録の無いもの。
- `prepend` を使ったクラス。別名 (alias) を Proc にしたもの。
- VM を開いた直後からあったのに名前の付かないオブジェクト。
- permanent な String / Array / Hash の中身が変わっている (v0 は permanent への
  変更をクラス・ivar・グローバル変数に限る)。
- Fiber や Task の中にいるとき、Task が残っているとき。
- C の関数が呼んだブロックの中 (`sort { }` など) で要求されたとき。C の関数の
  フレームは運べないので、要求された時点で断る。

## 12. v0 で決めていないこと

- デバッグ情報 (行番号) は P3 で §14 の `DBG0` として足した。
- Fiber・Task・C のデータの汎用の扱い。
- 形式の圧縮、改ざんの検出、暗号化。
- 処理系をまたぐ permanent の対応表 (P2 で SabiRuby 側に作った。表ではなく名前を
  引く手順。§8)。
- 形式の版は v0 のまま (P2 の追補は種類を足しただけで、P1 の読み込み側は知らない種類を
  断る。黙って読み違えることはない)。

## 13. P3 の追補: オブジェクト・Proc・クラス・変更

P3 (試験一式をランダムなセーフポイントで往復させる) で、運べずに断っていたものを運ぶために
足した。並びは変えていない。P2 までの読み込み側は知らない種類を断る。

### 13.1 オブジェクトの種類 (§7 の表の続き)

| 種類 | 名前 | 共通ヘッダの後 |
|---|---|---|
| 16 | 64 bit に収まらない Integer (bigint) | `u8` 負なら 1 + `str` 絶対値の 16 進の数字 (ASCII、小文字) |
| 17 | Struct | `u32` 個数 + 各 `値` (メンバの値。メンバの名前はクラスの側にある) + ivar の並び |
| 18 | Set | `u32` 個数 (`0xffffffff` は Set.allocate のまま初期化されていない) + 各 `値` (要素。読む側は全部そろってから入れ直す、Hash のキーと同じ) + ivar の並び |
| 19 | Rational | `str` 分子 (10 進) + `str` 分母 (10 進) |
| 20 | Complex | `u64` 実部 + `u64` 虚部 (IEEE 754 倍精度のビット列) |
| 21 | break (ensure 節を通る break・return・jump の途中の内部オブジェクト。レジスタにだけ現れる) | `u8` 種類 (0 = break、1 = jump、2 = stop: mruby 4.0 の `RBREAK_TAG`) + `u32` 行き先のフレームの番号 + `値` |
| 23 | Random (mruby-random) | `u64` PCG の状態 + `u32` 最後のシード + ivar の並び |
| 24 | 前置きされたクラスの origin (prepend されたクラスの元のメソッドを持つ取り込みクラス) | (共通ヘッダのクラスは、そのクラス自身) `ref` スーパークラス + `u8` メソッド表があれば 1 + `u32` メソッドの数 + 各メソッド |
| 25 | String (binary のフラグつき: `String#b`) | 種類 3 と同じ |

- 22 は使っていない。
- **Hash と Set の入れ直しの順**: 読む側は、番号の大きいものから入れる (Hash や Set を
  キー・要素に持つものは、その中身がそろってから計算し直す。書く側は外から順に番号を
  振るので、中のものほど番号が大きい)。
- キー・要素の `hash` / `eql?` が利用者のメソッドなら、入れ直しで呼ばれる (Marshal.load と
  同じ)。それが例外を上げたり、入れ直している Hash の大きさを変えたりしたら、復元を断る。

**種類 14 (C のデータ) の追補**: 型の名前が空 (`""`) のものは、型も中身もまだ無い
(`Regexp.allocate` などで作っただけ) C のデータ。中身の `str` は空。

C のデータの型ごとの中身 (書く側の `checkpoint_bundled.c`、mruby の付属の gem の型):

| 型の名前 | 中身 |
|---|---|
| `Time` | `u64` 秒 (int64) + `u64` ナノ秒 (int64) + `u8` 時間帯 (1 = UTC、2 = 地方時) |
| `Regexp` | 空。パターンとフラグは ivar `@source`・`@flags` にあり、読む側はそれから組み立て直す |
| `MatchData` | `u64` 捕獲の数 n + 2n 個の `u64` (各捕獲の始まりと終わりのバイト位置、int64、無しは −1)。元の文字列と Regexp は ivar `source`・`regexp` にある |
| `CombinationState` (`Array#combination` などの途中) | `u64` k + `u64` n + `u64` 方式 (mruby-array-ext の番号) + `u8` 位置の表があれば 1 + k 個の `u64` 位置 |
| `ary_product_generator` (`Array#product` のブロック付きの途中) | `u64` 全体の数 + `u64` いまの位置 |

### 13.2 Proc の本体の種類 (§7 の Proc の中身の追補)

| 本体の種類 | 中身 |
|---|---|
| 2 = 別名 (`alias_method` で Ruby のメソッドに付けた名前) | `sym` 元のメソッド名。外側の Proc (`upper`) が元のメソッドの Proc |

C の関数の Proc の引数の仕様: 最上位ビットが立っていて下位 31 bit が 0 のものは、
「引数を数えない」(attr_writer の Proc など)。最上位ビットが 0 のものは「引数なし」。

### 13.3 クラスの中身の追補

フラグの `u8`: bit2 = prepend されている (メソッドは種類 24 の origin にある)、
bit3 = メソッド表を持つ (空でも。mruby はクラスを作るときに表を作り、prepend の循環の
検出などで表の同一性を使う。特異クラスは最初は持たない)。

Range の終わりの `u8`: bit1 = まだ初期化されていない (`Range.allocate`)。始めと終わりは
nil で、意味を持たない。

### 13.4 permanent なものの名前の追補 (§8)

- `BasicObject` のように、定数がそのクラス自身の中にしかないクラスは、子のクラスを
  なめるときにスーパークラスとして名前を付ける (クラスのパス)。
- 定数・ivar が指すただのオブジェクトに特異クラスがあれば `S:<名前>` (ENV のメソッド)。
- 実行中に作られるクラスに gem が入れる C の関数 (`Struct.new` と `Data.define` の作る
  クラスのアクセサ・`members` など): 作るクラスの中の名前で `F:Struct.new#a`、
  `F:S:Struct.new#members` (メンバ `a`〜`f` で 1 度作って名前を取る)。
- 埋め込む側が名前を付けた C の関数 (`mrb_checkpoint_register_func`): `F:<その名前>`。
- VM を開いた直後のオブジェクトは、プログラムが参照を手放しても回収されない (書く側も
  読む側も、隠した Array で持つ)。名前とアドレスの対応が崩れないようにするため。

### 13.5 変更表の種類 (§9 の続き)

| 種類 | 名前 | 中身 |
|---|---|---|
| 8 | permanent な Random の状態 (既定の乱数) | `ref` オブジェクト + `u64` 状態 + `u32` 最後のシード |
| 9 | permanent なクラスのマーカー | `ref` クラス + `u8` bit0 = prepend されている (1 ならスーパークラスのチェーンの中に種類 24 の origin がある) |
| 10 | permanent な String / Array / Hash の中身 | `ref` オブジェクト + `u8` frozen + `u8` 型 (3 / 4 / 5) + 中身 (String: `str`、Array: `u32` + 各 `値`、Hash: `u32` + 各 (`値`, `値`)。Hash は他の Hash と同じく最後に入れ直す) |

permanent な Hash の ivar (既定値) の変更は種類 3 で現れる。

## 14. 任意のセクションと終端タグ (P3)

VM の部分の後に、タグ 4 バイトで始まるセクションが 0 個以上続き、最後に `END0` が来る。読む側は
知らないタグに出会ったら断る。

| タグ | 中身 | 読む側 |
|---|---|---|
| `DBG0` | `u32` 個数 + 各 (`ref` irep (運ぶ irep の番号) + `u16` ファイルの数 + 各ファイル (`str` ファイル名 + `u32` 始まりの pc + `u32` 終わりの pc + `u32` 個数 + 各 (`u32` pc, `u32` 行) 行が変わる位置)) | 運んだ irep に行番号を付ける。permanent な irep は自分のを使う。無視してもよい (バックトレースに行番号が出ないだけ) |
| `GCS0` | `u8` (bit0 GC を止めている、bit1 世代別、bit2 割り当てごとに進める、bit3 スケジューラが進める) + `u32` interval_ratio + `u32` step_ratio + `u64` step_limit + `u64` malloc_threshold + `u64` debt_limit (int64) | GC の設定に当てる。書く側は VM を開いた直後と違うときだけ書く。GC の作りの違う処理系は無視してよい |
| `END0` | なし | ここで終わる |

## 15. 外からの要求 (P3)

`mrb_checkpoint_request()` は、プログラムが `Checkpoint.save` を呼ばずに、外から書き出しを
要求する API。イメージの形は同じで、書き出す点が「要求の後の最初のセーフポイント」になる。いちばん上のフレームの
どのレジスタも書き換えない (`:resumed` は入らない)。

## 16. P3 で運べないもの (§11 の改訂)

- Fiber・Task (いま動いているものも、値として持っているだけのものも)。形式はルートの
  コンテキストしか持たない。
- C の関数が呼んだブロックの中 (C の関数のフレーム)。
- 開いているファイル・ソケット・ディレクトリ (プロセスの資源)。
- ObjectSpace からしか届かない、VM を開いた直後のオブジェクト (名前が無い)。
- 名前の無い C の関数から作った Proc (`mrb_checkpoint_register_func` で名前を付ければ運べる)。
- キー・要素の `hash` / `eql?` が入れ直しで例外を上げる・Hash を変える Hash や Set (復元で断る)。
