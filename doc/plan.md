# mruby-checkpoint: mruby の VM の実行状態を運ぶ原理検証

> 状態: 進行中 | 更新: 2026-11-03 | mruby 単体と SabiRuby 単体で、VM の実行状態を書き出して続きから動かせることを確かめる

## 目的

mruby の VM で動いているプログラムを、アプリの協力なしに途中で止め、状態を
書き出し、別の場所で続きから動かす。まずボードも OS も無しに、mruby 単体
(と SabiRuby 単体) で原理を確かめる。結果は後で Family mruby へ持ち込む。

## 方針

- **論理グラフ方式に一本化する**。生のメモリの丸写しはしない。オブジェクトに通し
  番号を振り、各レコードは「型タグ + フィールド (参照は番号)」。同じプロセスでも
  別のアーキテクチャでも同じコードで運ぶ。
- **普段の実行では何もしない。コストは運ぶ瞬間にだけ払う**。実行中の内部表現
  (ポインタ・シンボル ID・irep) は変えない。シンボルは名前で、irep は中身の
  ハッシュで、cfunc は「クラス名#メソッド名」で書き出し、着いた先で引き当てる。
- **形式は mruby の意味論の層で定義する** (C の mruby の構造体の写しにしない)。
  SabiRuby でも読めることが、それを確かめる手段になる。
- **mruby 本体への patch は最小にする**。本体側は安全点への相乗りくらいに抑え、
  直列化・復元は独立した gem (`mrbgems/mruby-checkpoint`) に置く。RData の dump /
  restore は `mrb_data_type` に欄を足さず、「`mrb_data_type` のポインタ →
  コールバック」の別表に登録する。
- **安全点は既存のタスク切り替えの判定に相乗りする**。`vm.c` の
  `RETURN_IF_TASK_STOPPED` と `task_across_c_boundary()` (上流 `d2a1c43a5`) により、
  「いつなら運べるか」は「いつならタスクを切り替えられるか」と同じ条件になる。
- mruby は Family mruby と同じ版 (`f56d44ecc`、4.0.0 系、RITE 04.00) と同じ値の
  表現 (`MRB_NO_BOXING`・`MRB_INT64`、Float は double) に合わせる。違うのは
  ポインタの大きさだけで、64bit 版と `-m32` の 32bit 版の間で運んで確かめる。

## スコープ

1. 形式の v0 の仕様書。
2. mruby 単体で、同じプロセスの中の往復 (新しい `mrb_state` へ復元)。
3. mruby の 64bit ⇔ 32bit の往復 (別のプロセス)。
4. mruby → SabiRuby の片道。
5. mruby の試験一式をランダムな安全点で往復させ、往復なしと完全に一致するか。

範囲外 (後の段か Family mruby 側): 窓・APU などの資源の作り直し、PSRAM の使い方、
ネットワーク越しの転送、pre-copy、暗号化。

## 受け入れ条件

- カウンタのプログラムが、`Checkpoint.suspend` の次の行から、別のプロセス (64bit → 32bit と
  32bit → 64bit) で数え続ける。
- 対応していない型を持つ状態は、理由を出して書き出しを拒否する (黙って壊さない)。
- 改造の前後で、mruby のベンチマークの普段の速さの差が 1% 以内。ホストでは valgrind
  の命令数で比べ、時間は ESP32 で測る (ホストの時間は `mrb_vm_exec` の命令の配置で
  ±10% 動くため。`doc/report/p1.md` の追加の調査)。
- (5 まで進んだら) 試験一式のランダムな安全点での往復が、往復なしと完全に一致する。

## 決まったこと (2026-11-02)

- SabiRuby 側の変更は、SabiRuby のリポジトリの中の feature (既定は off) として
  ブランチで足す (feature 名は P2 で決める)。計画は SabiRuby の `docs/plans/` に
  作者向けの案として置く。
- P2 では、止まっていたフレームが指す mrblib の irep だけ中身も運び、他の mrblib は
  名前で引き当てる (SabiRuby の mrblib は 4.1.0-rc2 で作られ、ハッシュが合わない)。

## 決まったこと (2026-11-02、P1b)

- 汎用の機能の名前は `mruby-checkpoint` (Linux の CRIU と同じ言葉)。Ghost の名前は
  この上に作るデモの層にだけ残し、このリポジトリからは消す。
- Ruby の口: `Checkpoint.save(path)` は書き出して動き続け、`Checkpoint.suspend(path)`
  は書き出してプロセスを終える。どちらもドライバの `resume` で次の行から続く。
  呼び出しの戻り値は、書いた側が `:saved`、復元した側が `:resumed`。
- 止め方は P1 のまま (印を立て、呼び出しの直後の安全点で書き出す)。C の関数が
  呼んだブロックの中で頼んだら、その時点で `Checkpoint::Error` にする (先送りしない)。
- 像の拡張子は `.ckpt`、形式の先頭の印は `MRCK`。形式の版は v0 のまま。

## 決まったこと (2026-11-03、P2 の検収)

- mrblib の irep は、生きたフレームが指すときに中身も運ぶ (P2 の実装のまま。1 像あたり
  59〜254 バイト)。
- 形式の版は v0 のまま (種類を足しただけ。外に読み手がいない間は、形を変えるときに
  まとめて v1 にする)。
- 試験の像 29 個 (約 55 KB) は SabiRuby の公開のリポジトリに置く。
- 死んだレジスタ (使われないのに古い値が残っているもの) を nil にして書く処理は P3 で
  入れる (ランダムな安全点で止めると増えるため)。

## 決まったこと (2026-11-03、P3 の途中)

- 判断の方針: 手間がかかっても、断る・除外する・避けるより、正しく運ぶ直し方を取る。断るのは
  原理的に運べないもの (C の関数の枠など) だけにし、理由を出す。食い違いは原因を直し、除外は
  正当な違い (object_id・時刻・乱数など) に限って理由と一緒に表にする。形式・方式の作り直しに
  なるなら止まって返す。

## 決まったこと (2026-11-03、P3 の検収のあと)

- P4 で Task と Fiber を運ぶ (Family mruby はアプリの本体を Task で走らせるので必須)。
  形式は P4 で v1 にする。P5 で可視化 (呼び出しの枠・オブジェクトのつながり・2 つの像の差・
  Task と Fiber)。GUI (Asterism の console か端末のアプリか) は P5 のあとで決める。

## 親の仮決め (2026-11-03、ユーザが寝ている間。あとでユーザが見直す)

ユーザの指示「問い合わせずにおすすめで進め、あとでチェックする」「楽をせず本質的な対応」に
よる。どれも、ひっくり返すときは該当の段の report から辿れる。

- (P3 の問い 2) permanent のオブジェクト (基準) は、隠した Array で全部生かしておく。
  `remove_const` などで消えたクラスの場所が別物に使い回され、名前の引き当てが別物を指す
  のを防ぐため。費用は Array 1 個と、本来なら回収されるはずの permanent の分。
- (P3 の問い 3) 復元は Hash・Set の鍵の利用者の `#hash`・`#eql?` を呼ぶ (CRuby の
  `Marshal.load` と同じ)。そこで例外が出たり Hash が変わったりしたら復元を断る。
- (P3 の問い 4) 同梱の gem (Time・Regexp・MatchData・組み合わせの反復の状態) の内部の
  構造体を写した `checkpoint_bundled.c` は mruby-checkpoint に置いたままにする。gem の側が
  構造体を変えたら追従が要る。Family mruby に持ち込むときに、gem 側に書き出しの口を
  置く形へ移すかを決め直す。
- (P3 の問い 5・6) 終わりの印 `END0` は必須のまま (P2 の像は読めない。外に読み手が
  いないため)。形式の版は P3 では v0 のまま、P4 で v1 にする。
- (P4) 起きる時刻は残りの tick で運ぶ。アプリの本体の Task も普通の Task と同じに運ぶ
  (指示書 `doc/instruction_p4.md`)。
- (P4 の検収、決めてほしいこと 1) 走っていた Task の時間の割り当ては、**残りを運ぶ**のを既定に
  する。P4 の指示書では「満タンから」と仮決めしたが、満タンでは横取りの位置がずれて往復なしと
  違う場合があった (`doc/report/p4.md`)。P4b で直す。
- (同 2) 着いた先の時計は書いたときの tick にする (サブの仮決めのまま)。Family mruby では
  アプリごとに VM を作るので、この形が取れる見込み。持ち込むときに確かめる。
- (同 4) 外からの要求と `Task.pass` が重なると pass が失われる穴は、認めずに塞ぐ。命令の境目の
  費用を増やさず、mruby-task の側が切り替えの頼みを記録する形にする (P4b)。
- (同 5) SabiRuby の試験の像 91 個 (約 240 KB) を公開のリポジトリに置くのは認める。
- (同 3) 上流の不具合 U1〜U5 (mruby-task・mruby-fiber、checkpoint なしで起きる) を報告するかは
  外へ出すことなので、ユーザが決める。

- (P4b の検収) 安全点の hook が Ruby を呼んで呼び出しの枠の表を動かしたあと、VM が古い枠を
  使い続ける不具合 (P3 からあった、普段のビルドにも響く) は、`vm.c` の patch の遅い側で枠を
  取り直して直す。命令数は ao_render で +0.115%、ほかはほぼ 0。書き出しを別の文脈で動かす案は
  hook から Ruby を呼べなくなるので採らない。
- (同) mruby-task の切り替えの頼みを数える patch (`patches/0002`) は手元に置く。上流へ出すかは
  U1〜U5 と一緒にユーザが決める。
- (同) mrblib の行番号のための静的データ (32bit で約 58 KB) は、原理検証では払う。Family mruby に
  持ち込むときに払うかは、そのとき決める (flash の定数のほか、VM を開くたびに行の表を VM の
  プールに読み込む分がある。どちらも測ってから)。

- (P5 の検収) 任意の節に長さを持たせる (v1 の中の変更。外に読み手がいないうちに入れ、知らない節を
  読み飛ばせるようにする)。P5b で入れる。
- (同) 同じプロセスで 2 回 save した像のオブジェクトを正確に対応させる節 (オブジェクトの身元) は
  後回し。差は根からの道筋で取り、動いたものも見分けられている。
- (同) 画面の言葉は日本語のまま (発表で英語が要るかはユーザが決める)。画面の写しの PNG は git に置く。
