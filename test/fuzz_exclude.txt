# Tests whose result may legitimately change when a checkpoint falls inside
# them (tools/fuzz.rb). They are run and counted like every other test; a
# difference whose first differing line belongs to one of these assertions is
# reported as expected instead of as a failure.
#
# file | assertion (the start of its line in the verbose output) | when | reason
# "another process": counted as expected only when the same run kept in one
# process (--xproc 0) gives the reference output. "as-task": only in the runs
# with --as-task (the program is a Task); elsewhere the test must not differ.
# "sabiruby": only when the image goes on in SabiRuby (tools/fuzz_sabiruby.rb, another VM).
core/proc.rb | identity check for proc object | in-process | Proc#hash is computed from the addresses of the irep and the Env (proc.c proc_hash); a restore gives new addresses, so a hash taken before the checkpoint and one taken after differ
mruby-method/method.rb | to_s | in-process | the expected string is built from the inspect of a singleton class (#<Class:#<Object:0x...>>, an address) before the checkpoint and compared with an inspect made after it
mruby-io/io.rb | IO | another process | the tests keep a file descriptor as an Integer (IO.sysopen) and make an IO of it later; a descriptor is a resource of the process, which the image does not carry (O_CLOEXEC), so in another process the number is not open (EBADF)
mruby-object-ext/object.rb | instance_exec on primitives with class and module definition | as-task | inside a Task (--as-task), instance_exec on an Integer crashes mruby itself, without any checkpoint: the block's frame has no target class (an Integer has no singleton class), and mruby-task reads that as the return from a context switch while the Task's context is marked vmexec, so mrb_vm_exec returns in the middle of the Task and the scheduler runs it on from past the end of its code (reading past the bytecode; the reference run ends with SIGSEGV). Where the read goes afterwards depends on the memory layout, which a restore changes
core/kernel.rb | Kernel#hash | in-process | the test compares two calls of hash on main; Kernel#hash is made from the object's address (object_id), and main of the restored state is another object at another address, so a checkpoint between the two calls changes the value (like Proc#hash above)
mruby-io/file.rb | File | another process | File#initialize (mruby-io's mrblib, in Ruby) holds the descriptor it opened as an Integer (File._sysopen) and gives it to IO#initialize afterwards; an image taken between the two carries the number, which in another process is not that file (it may be another one, or none), so a later test there reads or writes something else
mruby-io/file_test.rb | FileTest | another process | the tests make an IO of IO.sysopen's descriptor (IO.new(IO.sysopen(...))); an image taken between the two calls carries the number as an Integer, and in another process that descriptor is not open (EBADF when the IO is used), as for io.rb above
core/array.rb | Array#hash | sabiruby | the test compares two calls of hash on equal Arrays; on SabiRuby (tools/fuzz_sabiruby.rb) the first one may have been computed by C mruby before the image and the second by SabiRuby, whose hash function is another (hash values belong to the VM that computes them)
